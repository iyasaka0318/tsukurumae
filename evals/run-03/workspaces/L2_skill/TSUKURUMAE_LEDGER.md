# 研究室 電子錠 保守 台帳
最終更新: 2026-10-06

## 概要
- 作るもの: 既存の電子錠アプリの保守（不具合調査）と改修
- 分野: 両方（Raspberry Pi 3 + FeliCa リーダー + 錠の駆動、Kotlin アプリ、pi4j）
- 用途: 実用（研究室の入退室）
- 目的: (1) FeliCa リーダーが時々無反応になる問題を、USB の抜き差しなしで解消する (2) Discord 通知を改修する
- 成功条件: 未決（Q4, Q5）。仮：(1) 無反応が起きない、または人手なしで自動復旧する (2) 改修内容は Q4 の答えで決める
- 優先順位: 仮定：入室できること（錠の動作）> 通知 > その他

## 仮定
| ID | 内容 | 確かめる方法 | 外れたときの影響 |

| A2 | pigs 方式のために実機で pigpiod の有効化などを行っている | O2 のコマンドで確認 | pi4j に戻した後、GPIO の初期化失敗・取り合いで錠が動かない可能性 |
| A3 | 書き換えはその3ファイルだけで、ビルド設定（pi4j の依存）は変えていない | 戻す元のコミットとの差分を見る | 3ファイルだけ戻してもビルドが通らない |
| A1 | アプリは systemd のサービスとして root で動く | `systemctl` で unit と User= を見る（O1） | 再現・観測のコマンドの実行ユーザーが変わる |

## 原因の候補（未検証）
| ID | 候補 | 区別する観測 |
|---|---|---|
| H1 | 電源不足（Pi 3 の USB 給電・低電圧）でリーダーが落ちる | `vcgencmd get_throttled`、dmesg の under-voltage |
| H2 | USB デバイスが切断・再接続され、アプリが古いハンドルを持ち続ける | 無反応中の `lsusb` と dmesg の disconnect / new device |
| H3 | リーダー側（ファーム）が固まる。USB 上は見えている | lsusb に見えていて dmesg に何もない。アプリ再起動で直るか |
| H4 | アプリ側の読み取りスレッドが固まる・例外で止まる | 無反応中のスレッドダンプ、アプリログ。アプリ再起動だけで直るか |
| H5 | カーネルドライバとユーザー空間ライブラリの取り合い | `lsmod` で port100 / pn533 等。方式が分かってから |
