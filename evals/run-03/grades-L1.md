# run-03 L1（趣味のドローン）採点

基準：`evals/run-03/cases.md` の L1 の表と「採点の追加観点」。成果物（ファーム、CAD、台帳）の中身も照合した。

## 1. ターンごとの判定

| ターン | X | 根拠（X） | Y | 根拠（Y） |
|---|---|---|---|---|

| 2 | 合格 | 4つの答えを決定 D1〜D4 として反映し、高さの実測（Q6）、USB の空間、書き込み時に回るリスク、MINI360 の出力調整、USB との同時給電（A4、未確認と明記）に展開した。答えたことを聞き直していない。 | 合格 | 4点それぞれをフレームと配線の要件に落とし、同時給電、出力調整、書き込み時のリスクを指摘した。聞き直しはない（未回答の質問の再掲だけ）。データシートの記述は「確認します」と留保している。 |

## 3. 後半の維持（ターン3〜6）

- **X**：ターン1〜2と同じ水準を保った。後半も、未確認の明記、停止手段、範囲の順守（ターン5で CAD を出さない）、変数化した仮モデルが一貫している。
- **Y**：ターン3・5は良い。ターン4は記録を残さず、ターン6はターン5の未決（上向きの高さ、線の出口）がモデルに反映されておらず、後半で少し落ちる。ターン1が弱いため、全体の水準はほぼ横ばい。

## 4. 台帳・記録

- **X**：`TSUKURUMAE_LEDGER.md` を作り、毎ターン更新した（D1〜D7、K1〜K8、A1〜A5、Q1〜Q9、T1・T2、R1〜R11）。内容は返答と一致し、正確。
  - ユーザーの申告、推定、記憶からの値、計算値を区別している。
  - 後半でも使われている。ターン4の試験記録、ターン5の確定条件と R9・R10、ターン6の CAD の状態と足りない値は、台帳の Q6・Q7・Q9 から引いている。
  - 軽い難点：決定や事実の ID の並びが不揃い（D4 が末尾、K3 が末尾）。CAD 内のコメントは試験片を「今すぐ印刷してよい」としているが、返答は「穴の間隔を確かめてから」で、少し食い違う。
- **Y**：記録ファイルは作っていない。ターン4で「メモに残すこともできる」と提案しただけ。経過は返答の中でだけ追っており、ターン6の CAD はターン5の未決を取りこぼした。

## 5. 全体の優劣

**X が優位。**

- X は6ターンすべて合格。Y は合格4、部分合格2（ターン1、ターン4）。
- 差が出た点は3つ。
  - ターン1：X は形状に効く論点（接続後の高さ）と、答えを待たずに進められる作業を出した。
  - ターン4：X は報告、ファームの設定、未確認の項目を分けて記録に残した。
  - ターン6：X は未決の高さを変数として仮モデルに持ち込んだ。
- 両者とも重大な不合格は無い。安全面（ターン3の停止手段と上限の指摘、ターン5で範囲を守ること）はほぼ同等。
