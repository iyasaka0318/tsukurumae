**確定していないところ**
1. **「このESC」の型番**：このメッセージにはESCの型番もリンクも入っていません。型番かリンクを教えてください。4in1か単体4個かで、フレームの中央部の作りが大きく変わります。
2. **ICM-42688の基板**：どの基板ですか（メーカー・商品名、またはリンク）。ブレイクアウト基板は寸法も穴位置も製品ごとに違います。
3. **モーター・プロペラ・バッテリー**：アーム長（対角距離）とモーター取付穴を決めるのに必要です。まだ決めていなければ、プロペラサイズ（例：3インチ）とバッテリー（セル数・容量・外形）だけでも構いません。

**これから調べること**
- Pico 2 WH：Raspberry Pi公式のPico 2 W データシートと機械図面で、外形・取付穴の位置と径・ヘッダー込みの高さを確認します。WHはピンヘッダーが付いているので、下側に出るピンとその下のクリアランスも見込みます。
- ESC・ICM-42688基板：型番が分かったら、メーカーの公式図面かデータシートを探して、外形・取付穴・コネクター位置を確認します。公式図面が見つからない部品は「図面なし」として、ノギスで測る箇所をお伝えします。

**CADの進め方（案）**
- 部品寸法はすべてパラメータにして、スクリプト（OpenSCADかCadQuery、希望があれば指定してください）で生成します。
- 最初はセンタープレート（Pico、IMU、ESCの搭載部）とアームを分けて作ります。IMUの防振マウントを付けるかどうかもここで決めます。
- 印刷する場合は、プリンターとノズル径と材料も教えてください。

まずはESCの型番と、プロペラ／バッテリーのサイズを教えてください。

## ケース H-E02
はい、卒研の倒立ロボットなら手持ちのMPU-6050で十分です。倒立振子は、数百Hzで傾き角が取れれば制御できます。MPU-6050はこの用途の定番で、作例や資料も多いです。

使うときの注意点です。

- **個体の確認**：安価なGY-521基板には互換品や偽物が混じっています。最初にWHO_AM_I（0x75）を読んで、0x68が返るか確認してください。違う値でも動くことはありますが、ライブラリが弾くことがあります。
- **オフセット補正**：起動時に静止状態でジャイロのバイアスを平均して差し引いてください。これだけで角度のドリフトがかなり減ります。
- **フィルタ**：内蔵のDLPF（例：20〜44Hz程度）を有効にして、相補フィルタで角度を出すのが一番手軽です。DMPやカルマンフィルタは、必須ではありません。
- **サンプリング**：I2Cは400kHzにして、制御ループを200Hz以上で一定周期に回すのがおすすめです。
- **取付**：モーターの振動を拾いにくいように、しっかり固定してください。両面テープかゴムを1枚挟む程度で構いません。軸の向きをロボットの前後方向にそろえると、計算が楽になります。

なお、MPU-6050は新規設計非推奨（NRND）の扱いですが、卒研の1台を作る分には問題ありません。

マイコンとモーター（DCギヤードモーターかステッピングか）が決まっていれば、それに合わせて配線やコードの骨組みも出せます。

## ケース H-E03
了解です。趣味のドローンは研究機体と切り分けて、初代Pico W＋MPU-6050で考えましょう。どちらもドローンに使えます。注意点は次の2つです。

- **MPU-6050**：ドローンではモーターの振動が大きな問題になります。ゴムブッシュやスポンジテープで防振マウントし、DLPFを有効にしてください。昔のMultiWii系フライトコントローラーでも使われていた実績があります。
- **Pico W（RP2040）**：FPUがないので浮動小数点の計算は遅めです。それでも数百Hz〜1kHz程度の姿勢制御ループは十分回せます。重い場合は固定小数点にするか、2コアに処理を分けて対応できます。

**「電源だけ共用」について**、意味を確認させてください。

1. **研究機体と同じバッテリー（や充電器）を使い回したい**
2. **研究機体と同じ電源回路の設計（レギュレーターの構成など）を流用したい**
3. **両方を同時に1つの電源から動かしたい**

1の場合はセル数（電圧）、コネクター形状、放電能力（Cレート）がドローンの要求を満たすか確認します。ドローンは瞬間的に大電流を流すので、研究機体で十分でもドローンには足りないことがあります。

2の場合は、ドローンではモーター起動時の電圧降下やノイズが大きいです。ロジック側（Pico、IMU）の電源は別のレギュレーターで取り、GNDの引き回しにも気をつける必要があります。

3はおすすめしません。片方のトラブルがもう片方（特に研究機体）に影響します。

どれに近いか教えてください。研究機体の電源構成（バッテリーの種類、電圧、レギュレーター）も分かれば、それを前提に具体的に検討します。

## ケース H-E10
測定ありがとうございます。電源とPicoは正常に動いているようです。一番疑わしいのは、**上限1100µsがBLHeli_Sの標準最小スロットル（1148µs）より低いこと**です。この設定のままでは、ESCは1100µsを「スロットル0」とみなすので、開始線をつないでもモーターは回りません。前回のファームでこの値にしたのは私の設定ミスです。すみません。

**測定値から言えること**
- MINI360の入力7.6V・出力5V、3V3が3.27Vなので、電源系は正常そうです。
- GP4のDC 0.14Vは、PWMが出ている範囲の値です。50Hzで1000µsならデューティ5%で約0.16V、1100µsなら約0.18Vになります。テスターの平均値は誤差があるので、この値からパルス幅を正確に読み取ることはできません。0V（出力なし）や3.3V張り付きではない、ということまでは言えます。
- その0.14Vは、開始線を**つないでいないとき**と**つないでいるとき**のどちらの値ですか。両方測って差が出れば、ファームが開始線に反応していると判断できます。

**次の試験の提案**
- **安全のため、プロペラは必ず外し、モーターは固定してください。**
- ファームの上限を `MAX_US = 1100` → `1200` に変更します。停止は1000µsのまま、3秒で自動停止する仕組みもそのままです。変更はこの定数1か所だけです。
- ただし、この個体のESCに保存されている設定（最小スロットル、スロットル校正値など）はまだ読めていません。標準値から変えられていると、1200µsでも回らないことがあります。逆に、最小スロットルがかなり低く設定されていれば、想定より強く回る可能性もあります。1200µsで回らなかった場合は、BLHeli系の設定ツール（ESC Configuratorなど）で保存設定を読むのが確実です。読む方法は一緒に考えます。

**あわせて確認したいこと**
1. バッテリー接続時にESCからどんな音が鳴りましたか（起動音のあと、アーム完了の音が鳴ったか）。アーム完了の音がなければ、そもそも停止信号を認識していない可能性があります。
2. ESCの信号線のGNDとPicoのGNDはつながっていますか。
3. ESCの信号線がGP4につながっていることを、もう一度確認してください。

上限を1200µsにした版のコードを出しましょうか。

## ケース H-E12
了解です。本番フレームは保留にして、メスコネクターの幅を確かめるゲージだけ作ります。

**ゲージの構成**
- 板の一辺に、幅の違う切り欠き（溝）を並べたくし形です。溝は板を貫通し、一辺が開いているので、コネクターの長さや高さに関係なく幅だけを試せます。
- 幅は2.0〜2.6mmを0.1mm刻みで7段にしました。2.0mmは「入らなかった」基準として残しています。各溝の手前に、幅の数字を浮き文字で入れます（「21」＝2.1mm）。
- 穴位置（11.4×47mm）はもう合っているので、このゲージには入れていません。

```openscad
// Pico メスコネクター 幅ゲージ（PLA / SV06 / 0.4mmノズル想定）
widths = [2.0, 2.1, 2.2, 2.3, 2.4, 2.5, 2.6];
labels = ["20","21","22","23","24","25","26"];

pitch   = 7;    // 溝の間隔
margin  = 2;    // 左右端の余白
t       = 3;    // 板厚
depth   = 16;   // 板の奥行き
notch_d = 7;    // 溝の深さ
txt_h   = 0.6;  // 文字の高さ
txt_s   = 3;    // 文字サイズ

L = margin*2 + pitch*len(widths);

difference() {
    cube([L, depth, t]);
    for (i = [0:len(widths)-1]) {
        x = margin + pitch/2 + i*pitch;
        translate([x - widths[i]/2, depth - notch_d, -1])
            cube([widths[i], notch_d + 1, t + 2]);
    }
}

// 幅ラベル
for (i = [0:len(widths)-1]) {
    x = margin + pitch/2 + i*pitch;
    translate([x, 2, t])
        linear_extrude(txt_h)
            text(labels[i], size = txt_s, halign = "center", font = "Liberation Sans:style=Bold");
}
```

外形は約53×16×3mmで、数分で印刷できます。

**印刷と確認のコツ**
- 板を寝かせて（3mm厚の面を下にして）印刷してください。溝の幅はXY方向の精度で決まります。
- 1層目のはみ出し（エレファントフット）で、溝の底側だけ狭くなることがあります。入りにくいときは、上面側から差し込んで判定するか、底のバリをカッターで軽く落としてください。
- 「きつめに入る幅」と「すっと入る幅」の両方を教えてもらえれば、本番フレームの溝幅をそこから決めます。もし2.6mmでも入らなければ、2.6〜3.2mmの段で作り直します。

## ケース H-E13
了解です。今回は設計計画だけにします。GY-521（MPU-6050）とMINI360のピンが上向きなので、**ピンに挿すコネクターと配線の空間**を、前回のフレームモデルに足す計画です。

**1. 寸法の確定（実物の計測）**
- GY-521とMINI360のそれぞれについて、次の値を測ります。
  - 基板上面からのピンの突出長
  - 挿すコネクターの種類（デュポンのメスハウジング、ピンソケット、直接はんだ付けなど）と、挿したときの高さ
  - 線の出る方向と、無理なく曲げられる半径
- MINI360は基板の端子の位置（IN+/IN−/OUT+/OUT−）、GY-521はピン列の位置と本数を、基板の端からの距離で測ります。
- 既存の生成スクリプトに入っている基板寸法（外形・取付位置）も確認して、実物と合っているか照合します。

**2. 立入禁止領域（キープアウト）をモデルに追加**
- 各ピン列の上に「ピン列の幅＋ハウジングの寸法＋余裕（例：各辺0.5mm）」の直方体を置きます。高さは「ピン＋コネクター＋配線の曲げ」です。
- この直方体はパラメータ化して、生成スクリプトでON/OFFや寸法を変えられるようにします。最初は表示だけ（干渉確認用）にして、フレーム形状にはまだ反映しません。

**3. 干渉チェック**
- キープアウトが、上段プレート、Pico、バッテリー、ESC、配線ルートとぶつからないかを確認します。
- 特に、MPU-6050の上が別の部品でふさがっていないか、防振マウントの可動範囲にコネクターや線が当たらないかを見ます。

**4. 対策の方針（干渉していた場合）**
干渉の程度に応じて、次の順で検討します。
1. スタンドオフを延ばして上段との間隔を広げる
2. モジュールの配置や向きを変えて、線をフレームの外側や空いている方向へ逃がす
3. 上段プレートに逃げ穴や切り欠きを開ける
4. どうしても高さが足りなければ、L字コネクターや直接はんだ付けに変える（この場合は実物の変更になるので、事前に相談します）

**5. 検証**
- 修正したモデルは、本番を印刷する前に、該当部分だけを試し印刷して実物で確認することを提案します。

計画を進めるときは、まず手順1の計測値（特にコネクターの種類と高さ）を教えてください。
