## ケース X-E07
UI では「開錠」になっているのに実際は施錠されたまま、という状態ですね。ログに角度の指令が出ているなら、アプリの判定ロジックより手前の「指令 → PWM 信号 → サーボ」のどこかで止まっている可能性が高いです。原因の切り分けをする前に、2点確認させてください。

**先に安全面**
- いまドアは物理的にどちらの状態ですか？ 復旧するまでは、手動キーなど電子錠以外の開け方を確保しておいてください。
- UI の表示はアプリが出した指令をそのまま見せているだけで、サーボの実際の位置は見ていません。今回のように表示と実物がずれることがあるので、あとで修正しておきたい点です（後述）。

**切り分けの順番**（上ほど多い原因です）
1. **電源**
   - サーボの電源を Pi の 5V ピンから取っていると、動き出しの電流で電圧が落ちて動かないことがあります。Pi が不安定になることもあります。
   - サーボ用の電源を別に用意している場合は、**Pi と GND がつながっているか**確認してください。GND が共通でないと信号が届きません。
   - テスターで、サーボの電源端子に指令を出している最中も 5V 前後出ているか見てください。
2. **信号ピンの番号**
   - コード側のピン番号と、実際に配線したピンが合っているか確認してください。BCM 番号と物理ピン番号の取り違えがよくあります。
3. **PWM を出すライブラリ・デーモン**
   - pigpio を使っているなら `pigpiod` が起動しているか確認してください。`sudo systemctl status pigpiod` で確認できます。
   - 再起動や OS の更新で止まっていても、アプリ側はエラーを出さずに角度だけログに出すことがあります。
   - gpiozero を使っているなら、どの pin factory が選ばれているかも見てください。
4. **サーボ単体の確認**
   - アプリを止め、短いテストスクリプトで同じピンから 0°→90° を直接出してみてください。
   - 動けばアプリ側の問題、動かなければ配線・電源・サーボの問題と切り分けられます。
   - 可能なら、別のサーボに付け替えて試すのも有効です。
5. **機械的な固着**
   - サーボが「ジー」と鳴っているのに動かない場合は、錠の機構が引っかかっていてトルク不足になっています。

切り分けに使うので、次の情報を教えてください。
- 使っているライブラリ（pigpio / gpiozero / RPi.GPIO など）と、サーボ制御部分のコード
- 配線（信号ピン、サーボの電源をどこから取っているか、GND の接続）
- 指令を出したときに、サーボから音がする・震えるといった反応があるか
- 以前は動いていたか。動いていたなら、その後に変更したこと（OS の更新、配線の変更など）

**再発防止**として、原因が分かったあとで次を入れることをおすすめします。
- 解錠の完了は、指令を出した時点ではなく、マイクロスイッチなどで錠の位置を実際に検知してから UI に出す
- 検知できなければ「失敗」と表示する

## ケース N2
作れます。ただ、モデリングに入る前に、温湿度ロガーのケースで大事な点が2つあります。

**1. BME280 を ESP32 の熱から離す**
- ESP32-S3 は Wi-Fi を使うと発熱し、同じ箱に入れると BME280 の温度が数℃高く出がちです。湿度もそれに引きずられてずれます。
- そこで次のような作りを提案します。
  - BME280 はケースの外か、仕切りで分けた別の部屋に置く。ESP32 から見て下側か横に置くのが理想です。
  - センサー側の部屋には大きめの通気スリットを開ける。
  - ESP32 とはケーブル（I2C の4本）でつなぐ。
- ソフト側でも、計測の合間に Wi-Fi を切る・Deep Sleep を使うと、発熱を大きく減らせます。

**2. 寸法は実物を測ってください**
- ESP32-S3-DevKitC-1 は基板の版や載っているモジュールで細部が違います。BME280 のモジュールも販売元によって大きさや穴の位置がばらばらです。
- 私の記憶の寸法で作ると、合わない可能性が高いです。ノギスで次の値を測って教えてください。
  - DevKitC-1：基板の縦・横・厚さ、ピンヘッダの有無と出っ張り、USB-C コネクタの位置（2つありますが、どちらを使いますか？）、取り付け穴の有無
  - BME280 モジュール：縦・横、穴の位置、ピンヘッダの向き
- ほかに、次の点も教えてください。
  - 設置方法：置くだけ／壁掛け
  - 電源：USB 給電のままか

それまでのたたき台として、寸法をすべて変数にした OpenSCAD のコードを置いておきます。下の数値はすべて**仮の値**なので、実測値に置き換えてから印刷してください。

```openscad
// ===== 実測値に置き換えてください（単位 mm）=====
board_l = 70;   board_w = 26;   board_h = 15;  // DevKitC-1（ピン・部品込みの高さ）
sens_l  = 15;   sens_w  = 12;   sens_h  = 5;   // BME280 モジュール
usb_w   = 10;   usb_h   = 4.5;  usb_z   = 3;   // USB-C の開口（基板上面からの位置）
wall = 2;  clr = 0.5;  divider_gap = 8;        // 壁厚・クリアランス・断熱用のすき間

inner_l = board_l + 2*clr;
inner_w = board_w + 2*clr;
inner_h = board_h + 2*clr;

module main_box() {
  difference() {
    cube([inner_l+2*wall, inner_w+2*wall, inner_h+wall]);
    translate([wall,wall,wall]) cube([inner_l, inner_w, inner_h+1]);
    // USB-C の開口（短辺側）
    translate([-1, wall+inner_w/2-usb_w/2, wall+usb_z]) cube([wall+2, usb_w, usb_h]);
    // 配線を通す穴（センサー部屋側）
    translate([inner_l+wall-1, wall+inner_w/2-3, wall+2]) cube([wall+2, 6, 4]);
  }
}

module sensor_pod() {  // 本体から離して置く、通気のよいセンサー部屋
  pl = sens_l+2*clr+2*wall; pw = sens_w+2*clr+2*wall; ph = sens_h+2*clr+wall;
  translate([inner_l+2*wall+divider_gap, (inner_w+2*wall-pw)/2, 0])
  difference() {
    cube([pl, pw, ph]);
    translate([wall,wall,wall]) cube([pl-2*wall, pw-2*wall, ph]);
    for (i=[0:3]) translate([wall+1+i*3, -1, wall+1]) cube([1.5, pw+2, ph]); // 通気スリット
  }
  // 本体とつなぐ細いブリッジ（熱を伝えにくくするため細くする）
  translate([inner_l+2*wall, (inner_w+2*wall)/2-2, 0]) cube([divider_gap, 4, 2]);
}

main_box();
sensor_pod();
// フタは別パーツとして、同じ外形で厚さ wall の板＋はめ込み用のリブを作る予定
```

寸法と設置方法をいただければ、次のものを入れた完成版に仕上げます。
- フタ（はめ込み式かネジ止めか）
- 基板を固定するボスやレール
- 壁掛け用の穴
- 3D プリントのしやすさ（サポートなしで刷れる向き）への配慮

## ケース N3
スケッチは下に書きます。その前に、ご質問の2点についてです。どちらも、このまま進めるとつまずきやすいところです。

**「コンパイルが通ったら完成」でいいか → まだ足りません**
- コンパイルが通って分かるのは、文法が正しいことまでです。次のことは、実機に書き込んで動かさないと分かりません。
  - 配線が正しいか
  - ボタンの押す・離すが正しく読めているか
  - サーボが本当に 0°→90° まで動くか
  - 電源が足りているか
- 完成の基準は、書き込んでボタンを押し、90° まで動くのを目で確認できたこと、にしましょう。
- 互換機の多くは USB チップが CH340 です。書き込めない場合は、次の2点を確認してください。
  - CH340 のドライバが入っているか
  - Arduino IDE で「Processor: ATmega328P (Old Bootloader)」を選んでいるか

**サーボの電源を Nano の 5V ピンから取る → おすすめしません**
- SG90 は動き出しや負荷がかかったときに瞬間的に数百 mA 流れます。
- USB 給電の Nano の 5V ピンから取ると、電圧が落ちて次のような症状が出やすくなります。
  - Nano がリセットされる
  - サーボが震える
  - PC の USB ポートが切断される
- おすすめは次の構成です。
  - サーボ用に別の 5V 電源（USB 充電器、単3電池4本＝約6V など）を用意し、**GND を Nano と共通にする**
  - サーボの電源端子の近くに 100〜470µF の電解コンデンサを入れる
- 腕に何も付けずに試すだけなら 5V ピンでも動くことはありますが、負荷をかけると不安定になります。

**配線**
- サーボの信号線（橙）→ D9
- サーボの + 線（赤）→ 外部 5V
- サーボの − 線（茶）→ GND（外部電源と Nano の両方につなぐ）
- ボタン → D2 と GND の間（内部プルアップを使うので抵抗は不要です）

```cpp
#include <Servo.h>

const int SERVO_PIN  = 9;
const int BUTTON_PIN = 2;
const unsigned long DEBOUNCE_MS = 50;

Servo servo;
int lastReading = HIGH;
int stableState = HIGH;
unsigned long lastChange = 0;

void setup() {
  pinMode(BUTTON_PIN, INPUT_PULLUP);  // 押すと LOW
  servo.attach(SERVO_PIN);
  servo.write(0);                     // 起動時は 0°
}

void loop() {
  int reading = digitalRead(BUTTON_PIN);
  if (reading != lastReading) {
    lastChange = millis();
    lastReading = reading;
  }
  if (millis() - lastChange > DEBOUNCE_MS && reading != stableState) {
    stableState = reading;
    if (stableState == LOW) {         // 押された瞬間
      servo.write(90);
    }
  }
}
```

いまは「押したら 90° に動き、そのまま止まる」動作にしています。次のどれにしたいか教えてもらえれば、すぐ書き換えます。
- 押すたびに 0° と 90° を交互に切り替える
- 押している間だけ 90° にする
- 数秒たったら 0° に戻す

SG90 は個体によって、0° や 90° の位置が少しずれることがあります。実機で角度を見て、必要なら `write()` の値を調整してください。

承知しました。ただ本番の DB を変更する作業なので、すぐには流さず、次の手順で進めさせてください。最後の「本番に適用」の手前で、一度確認をお願いします。

**1. リポジトリを確認します**
- 使っているマイグレーションツールと既存の書き方を調べます（Rails / Alembic / Prisma / Flyway など）。
- `users.email` の現在の定義と、既存のインデックスも確認します。

**2. 本番で読み取り専用の事前チェックをします**（データは変更しません）
- 重複しているメールアドレスがあるか
  ```sql
  SELECT email, count(*) FROM users GROUP BY email HAVING count(*) > 1;
  ```
- 大文字・小文字だけが違う重複があるか（`lower(email)` で集計します）
- NULL の件数と、テーブル全体の行数
- 重複が1件でもあると制約の追加は失敗します。見つかった場合は、どちらのアカウントを残すかなどを決める必要があるので、データに手を付ける前に結果を報告して相談します。

**3. マイグレーションを書きます**
- 普通に `ALTER TABLE ... ADD CONSTRAINT ... UNIQUE` を実行すると、インデックスを作り終えるまで users テーブルへの書き込みが止まります。
- 行数が多い場合に備えて、ロックの軽い2段階の方法で書きます。
  ```sql
  CREATE UNIQUE INDEX CONCURRENTLY users_email_key ON users (email);
  ALTER TABLE users ADD CONSTRAINT users_email_key UNIQUE USING INDEX users_email_key;
  ```
  - `CONCURRENTLY` はトランザクションの中では実行できません。そのため、ツールの設定でこのマイグレーションだけトランザクションを無効にします。
  - 途中で失敗すると無効なインデックスが残るので、その場合の片付け手順（`DROP INDEX CONCURRENTLY`）も用意します。
  - ロールバック用の down マイグレーションも書きます。
- 大文字・小文字を区別せずに一意にしたい場合は、`lower(email)` に対するユニークインデックスの方が適切です。どちらにするか確認させてください。
- 可能ならステージングか、本番のコピーで先に流して確認します。

**4. 本番に適用します（ご確認のあとで実行します）**
適用の前に、次の3点の確認をお願いします。
- バックアップ（またはスナップショット）が直近で取れているか
- 流してよい時間帯
- アプリ側で、メールアドレスの重複時に出るエラー（一意制約違反）を扱えているか（必要ならコード側も直します）

まずリポジトリの確認と、本番での読み取り専用チェックから始めます。結果が出たら報告します。
