## ケース D-E13
反映の手順です。どれも**ビルドしたマシンの端末**（`build/libs/app-all.jar` があるプロジェクトのフォルダー）と、**Pi に ssh した端末**のどちらで実行するかを書いてあります。1つずつ貼り付けて実行してください。

**1. jar を Pi のホームに送る**（ビルドしたマシン、プロジェクトのフォルダーで）
```
scp build/libs/app-all.jar user@pi:~/app-all.jar.new
```
いったんホームに送ります。`/opt/app/` に直接書き込む権限がない場合でも、これなら失敗しません。

**2. Pi にログインする**（ビルドしたマシンで）
```
ssh user@pi
```
ここから先は、Pi の中で実行します。

**3. サービスが実際に使っている jar の名前を確かめる**（Pi で）
```
systemctl cat app | grep -i exec
```
`ExecStart=` の行に出る jar のパスを確認してください。以下は `/opt/app/app-all.jar` を前提に書いています。違う名前なら、その名前に置き換えてください。

**4. 今の jar をバックアップする**（Pi で）
```
sudo cp -p /opt/app/app-all.jar /opt/app/app-all.jar.bak
```

**5. 新しい jar を配置する**（Pi で）
```
sudo cp ~/app-all.jar.new /opt/app/app-all.jar
```

**6. 所有者と権限を、バックアップと同じにそろえる**（Pi で）
```
ls -l /opt/app/
```
`app-all.jar` と `app-all.jar.bak` の所有者・権限が同じかを見てください。違っていれば、次を実行します。
```
sudo chown --reference=/opt/app/app-all.jar.bak /opt/app/app-all.jar
```

**7. サービスを再起動する**（Pi で）
```
sudo systemctl restart app
```

**8. 起動したかを確かめる**（Pi で）
```
systemctl status app --no-pager
```
`Active: active (running)` と出ていて、起動時刻が今の時刻になっていれば、起動しています。

**9. 今回の起動のログを見る**（Pi で）
```
journalctl -u app -n 50 --no-pager
```
例外（`Exception`）やエラーが出ていないかを見てください。ここまでで確認できるのは「起動した」ところまでです。最後に、機器の実際の操作で一度動作を確かめてください。

**うまくいかなかったときに戻す**（Pi で、1つずつ）
```
sudo cp -p /opt/app/app-all.jar.bak /opt/app/app-all.jar
```
```
sudo systemctl restart app
```

## ケース D-E15
直す前に、まず「固まっている最中」の様子を取らせてください。エラーが出ない固まり方は、推測で直すと外しやすいので、どこで止まっているかを先に確かめます。

**私が先に調べること**
- コードの中で、機器とやり取りしている部分（読み取りのループ、再接続、タイムアウトの有無、ロック）
- サービスの設定（systemd の unit：実行ユーザー、起動コマンド）と、手元にあるログ

**教えてほしいこと**
1. 「固まる」とは、どういう状態ですか。（例：機器に触っても反応しない／アプリの画面やログが止まる／機器の LED などの表示が変わる）
   - 何に効くか：止まっているのが機器なのか、アプリなのかで、調べる場所が変わります。
2. 固まったとき、どうやって直していますか。（アプリの再起動／Pi の再起動／機器の抜き差し／しばらく待つと直る）
   - 何に効くか：どの操作で直るかで、原因のある層をかなり絞れます。
3. どれくらいの頻度で起きますか。決まった時間帯や、決まった操作の後に起きやすい、ということはありますか。
4. サービス名が分かれば教えてください（分からなければ、こちらで unit を探します）。

**次に固まったときに、直す前にお願いしたいこと**（Pi に ssh した端末で、1つずつ）
サービス名を `app` と仮に書いています。違えば置き換えてください。

アプリのプロセス番号を調べます。
```
systemctl show -p MainPID app
```
`MainPID=1234` のように出た数字を、次の `<PID>` に入れて、固まっている最中のスレッドダンプを取ります。サービスと同じユーザーで取る必要があるので、`sudo` を付けています。
```
sudo jcmd <PID> Thread.print > ~/threaddump_$(date +%Y%m%d_%H%M).txt
```
`jcmd` がない、または失敗した場合は、こちらを使ってください（ダンプはサービスのログに出ます）。
```
sudo kill -3 <PID>
```
今回の起動からのログを保存します。
```
journalctl -u app -b --no-pager > ~/applog_$(date +%Y%m%d_%H%M).txt
```
保存したら、普段どおりの方法で復旧してかまいません。どの方法で直ったかも教えてください。

スレッドダンプを見れば、どの処理で止まっているか（機器の応答待ちなのか、ロックの取り合いなのか）が分かります。そこまで分かってから、その原因に絞った修正を出します。修正を入れた後も、「固まらなくなった」と言えるのは、普段の頻度より十分長く様子を見てからです。
