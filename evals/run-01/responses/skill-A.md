卒研の倒立ロボットを、高級機にはせず安く作りたい。手持ちの MPU-6050 で足りるか、というご質問と理解しました。

**今の見立て**
「倒立させて安定させる」ことが目的なら、MPU-6050 で作られた倒立ロボットは多く、手持ちを使う方向は十分に検討に値します。高い IMU に替えれば研究の質が上がる、というわけでもありません。
ただ、「足りるか」は**研究で何を評価するか**によって決まります。ここが分からないので、まだ確定はしません。

**判断を分けるポイント**
- 研究で比べるのが制御方式（PID と LQR など）なら、センサは条件を揃えるための土台です。必要なのは、制御周期に対して十分な更新レート、姿勢推定のノイズとドリフトの程度、比較の間ずっと同じ特性で動くことです。

- 手持ちの MPU-6050 は、GY-521 などの基板に載っていることが多く、チップの真贋や個体差が混ざります。比較実験の前に、静止した状態でのノイズとドリフトを測っておくと、後で「差がセンサのせいか」を切り分けられます。
- 予算は IMU よりも、モーター（エンコーダー付きか）、モータードライバ、電池、フレームのほうがずっと大きく効きます。安く作るなら、そちらを総額で比べるほうが効果があります。
- MPU-6050 は新しく買いにくくなっている可能性があります。現行品かどうか、予備を入手できるかは私が調べます（今は未確認です）。

**お聞きしたいこと**
1. **研究で何を比べ、何を評価しますか**（例：制御手法の比較、外乱からの復帰、特定の推定手法）：必要なセンサ性能と制御周期がここで決まります。
2. **何ができたら成功ですか**（例：○秒倒立、押されても復帰、指定の外乱に耐える）：検証の深さと、部品に求める余裕が決まります。
3. **マイコンと、モーター（エンコーダーの有無）は決まっていますか、手持ちはありますか**：I2C の速度と制御周期、総額の見積もりに効きます。
4. **予算の上限と、締め切り（中間発表など）**：候補の幅と、調達の納期に効きます。

**答えを待たずに進めること**
- MPU-6050 の仕様（出力レート、レンジ、ノイズ）と入手性を公式資料で調べます。
- 倒立ロボットを構成する部品の候補を、送料と周辺に必要なものまで含めた総額で並べます（価格は調べた日付付き）。

研究の内容が「制御手法の比較」なら、特に希望がなければ「MPU-6050 で進め、静止時の測定で問題がないことを確かめる」を仮の方針にします。

## ケース H-E10
報告ありがとうございます。確認した範囲を整理します。
- 5V 系と Pico の電源（MINI360 の出力 5V、Pico の 3V3 が 3.27V）は正常な値です。
- 6秒待ってから開始線を4秒つないでも、モーターは回っていません。

**最初に、私の生成物の問題です**
前に作ったファームウェアは、上限を **1100µs** にしていました。BLHeli_S の標準の最小スロットルは **1148µs**（公式の既定値）です。つまり、ESC が既定の設定のままなら、開始線をつないでも指令が「回り始める値」まで届かず、回らないのが当然の設計でした。安全のために低く抑えたつもりでしたが、ESC の仕様と照らし合わせていませんでした。申し訳ありません。

ただ、お手元の ESC の保存設定はまだ読めていないので、これが唯一の原因と決めつけることはしません。

**原因の候補**
1. 指令の上限（1100µs）が、ESC の始動する範囲より下にある。（最も有力。上の理由です）
2. ESC の個体に保存された最小スロットルが、既定の値と違う。（設定が未読なので、どちらにも振れます）
3. ESC がアーミングしていない（電源投入時に停止の信号を認識していない、または ESC 自体に給電されていない）。
4. 開始線の操作をファームウェアが認識していない（ピンの設定や、プルアップの扱い）。

**GP4 の 0.14V について**
50Hz・1000µs のパルスなら、平均電圧はおよそ 3.27V × 5% ≒ 0.16V の計算になります。0.14V はそれに近い値なので、「GP4 から何らかのパルスが出ている」ことと矛盾はしません。
ただ、テスターの直流電圧ではパルス幅や周期までは確かめられないので、「1000µs が正しく出ている」とまでは言えません。1000µs と 1100µs の違いも約 0.016V しかなく、テスターでは見分けにくいです。

**次に確かめたいこと（プロペラは外したまま）**
1. **ESC の電源を入れたときの音**：ピピッという起動音のあとに、アーミングの音が鳴るかどうか、何回鳴ったかを教えてください。候補 3 の切り分けになります。
2. **ESC の電源はどこから来ていますか**：MINI360 に入っている 7.6V と同じ電池から、ESC にも直接給電されているか。ESC の GND と Pico の GND がつながっているか。
3. 0.14V を測ったのは、開始線を**つないでいる間**でしたか、つないでいない間でしたか。

**ファームウェアの修正案（作り直します）**
停止 1000µs、50Hz、開始線を GND につないでいる間だけ回すこと、3秒の自動停止は、いずれも今のまま維持します。変えるのは上限だけです。
- 上限を一気に上げずに、**開始線をつなぐたびに 1150 → 1200 → 1250µs と1段ずつ上げ**、1250µs で頭打ちにします。
- 各回とも、つないでいる間だけ、最長3秒で 1000µs に戻ります。線を GND から離せば、その場で停止します。
- どの段で回り始めたかが分かれば、個体の最小スロットルの目安にもなります（候補 1 と 2 の区別）。
- 保存設定を BLHeliSuite などで読む方法もありますが、passthrough の接続が必要です。必要になったら、手順を別に用意します。

修正したファイルは、変更点（上限と、段階的に上げる処理）を明記してお渡しします。ビルドが通ることは確認しますが、実機で回るかは、試していただくまで未確認として扱います。

台帳には次を記録します。試験：ESC 単体回転、設定は 50Hz・1000〜1100µs・3秒自動停止、結果は回転せず。電源の実測（入力 7.6V、出力 5V、3V3 は 3.27V、GP4 の DC は 0.14V。いずれもユーザー実測、測った時の開始線の状態は未確認）。原因の候補 1〜4。AI 側の不備として、上限が BLHeli_S の既定の最小スロットルより下だったこと。

## ケース H-E12
了解しました。本番フレームには触れず、Pico の黒いメスコネクターが入る幅を調べるゲージだけを作ります。

**前提（いただいた情報）**
- 部品の幅：2mm 強（ユーザー実測、概数）。2.0mm のスリットには入らなかった（試験結果）。
- 穴位置 11.4×47mm は既に合っています。本番では維持し、このゲージには入れません。
- 材料は PLA、プリンタは SV06、ノズルは 0.4mm。段階的な幅で試すことに同意済み。

**ゲージの仕様**
- 貫通スリットを6本：幅 2.1 / 2.2 / 2.3 / 2.4 / 2.5 / 2.6mm
- スリットの長さは 12mm。板厚は 4mm。スリットの間隔は 6mm（壁は最低 3.4mm 残ります）
- 各スリットの横に、幅を ×10 した数字（21〜26）を彫り込みます
- 平置きで印刷します。スリットの壁は造形面に対して垂直になります

```openscad
// コネクター幅ゲージ v1  PLA / SV06 / 0.4mm ノズル
widths  = [2.1, 2.2, 2.3, 2.4, 2.5, 2.6];
slot_len = 12;   // スリットの長さ
plate_t  = 4;    // 板厚
pitch    = 6;    // スリットの中心間隔
margin   = 4;
label_h  = 6;    // 数字を彫る帯の幅

n = len(widths);
difference() {
  cube([margin*2 + pitch*(n-1), margin*2 + slot_len + label_h, plate_t]);
  for (i = [0:n-1]) {
    // スリット（貫通）
    translate([margin + i*pitch - widths[i]/2, margin, -1])
      cube([widths[i], slot_len, plate_t + 2]);
    // 幅の数字（×10）を 0.6mm 彫る
    translate([margin + i*pitch, margin + slot_len + 1.5, plate_t - 0.6])
      linear_extrude(1)
        text(str(round(widths[i]*10)), size = 3, halign = "center");
  }
}
```

**試し方と記録の仕方**
- 各スリットにコネクターを挿してみて、「入らない／きつい（入るが押し込む必要がある）／ちょうど／緩い（ガタがある）」の4段階で教えてください。
- 1層目がつぶれて広がると（エレファントフット）、下の面だけ狭くなることがあります。上の面から挿した場合と下の面から挿した場合で違うなら、それも教えてください。
- スライサーの水平方向の補正（Horizontal expansion など）を使っている場合は、その値も記録します。結果は、その設定の条件でだけ有効になります。

**確認したいこと（1点）**
- 「幅」は、コネクターのどの方向の寸法ですか（ピンが並ぶ方向に直角な厚み、で合っていますか）。挿す深さや、スリットの長さ方向に必要な長さがあれば教えてください。今は長さ 12mm で、幅だけを試す設計にしています。

**結果の扱い**
このゲージで合った幅は、「PLA・SV06・この板厚・平置き・このスリット形状」での試験結果として台帳に記録します。本番フレームに入れるときの適合は、保持の強さや隣の穴の周りの肉厚も関わるので、その時点では未確認として扱います。

台帳に記録すること：K＝コネクター幅 2mm 強（ユーザー実測、概数）、試験＝2.0mm のスリットに入らず、穴位置 11.4×47mm は合致済み（維持）、ゲージ v1 は幅 2.1〜2.6mm で結果待ち。

   各部品に「接続後の高さ」「ハウジングの外形」「線の出口の向き」「曲げのための余裕」を持たせ、その範囲に入る構造物を避けます。既に合っている寸法や穴位置は変えません。
5. **確認の段階**

**お聞きしたいこと**
1. **挿すコネクターの種類**（1ピンずつのジャンパ線か、複数ピンのハウジングか）：空間の幅と長さが決まります。

3. **線を引き出したい向き**（真上、横に寝かせる、どの辺から出すか）：配線の経路と、周りに空けるスペースが決まります。特に希望がなければ「挿した後に横へ曲げて、近い辺から出す」で計画します。
