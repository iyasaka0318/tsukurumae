## ターン 1

了解です、電子錠の Discord 通知を直しましょう。まず状況を教えてください。

1. **何が起きていますか？** 例：通知がまったく来ない／来たり来なかったりする／遅れて来る／二重に来る／内容がおかしい（文字化け、施錠・解錠が逆など）。
2. **いつからですか？** 何か変えた後（コードの更新、Wi-Fi やルーターの変更、Discord 側の設定変更など）からでしょうか、それとも最初から？
3. **構成**：通知を送っているのはどこですか？（例：ESP32 などのマイコンから直接 Discord の Webhook に送っている／ラズパイやサーバーを経由している／Bot を使っている）
4. **コードやログ**：通知を送る部分のコード、シリアルログやエラーメッセージ（HTTP のステータスコードなど）があれば貼ってください。

なお、コードやログを貼るときは **Webhook の URL や Bot のトークンは伏せてください**（URL を知られると誰でもそのチャンネルに投稿できてしまいます）。

ファイル一式がこのフォルダーにあるなら、場所を教えてもらえれば読んで原因を探します。

## ターン 2

ありがとうございます。「Raspberry Pi＋Kotlin で、ボタンを押したら Discord に通知、それがたまに来ない」ですね。先輩のコードということなので、まず中身を見て原因を絞りましょう。

### 「たまに来ない」でよくある原因

大きく分けて、**ボタンの押下を拾えていない**のか、**拾ったけど送信に失敗している**のかのどちらかです。

- **ボタン側**
  - GPIO を一定間隔で読んでいて（ポーリング）、短い押下を取りこぼしている
  - チャタリング対策（デバウンス）の待ち時間が長すぎて、2 回目以降の押下を無視している
  - プルアップ／プルダウンがなく、入力が不安定
- **送信側**
  - Wi-Fi が一時的に切れている、または省電力で反応が遅い
  - HTTP リクエストが失敗しても**再送しておらず**、エラーも握りつぶしている（`try { } catch (e: Exception) { }` だけなど）
  - Discord のレート制限（HTTP 429）に当たっている
  - タイムアウトや、コルーチン・スレッドが途中でキャンセルされている

### まず確認したいこと

1. **コードを見せてもらえますか？** このフォルダーに置いてもらえれば読みます。特にボタンを読む部分と、Discord に送る部分です。
2. **ログはありますか？** `journalctl` やログファイルなどに、ボタン押下や送信結果が出ていれば、来なかったときの時刻のものを見たいです。
3. **来ないときの状況**：連続で押したとき、しばらく放置した後、特定の時間帯など、何か傾向はありますか？
4. **どのくらいの頻度**で来ないですか？（10 回に 1 回、1 日に 1 回など）

切り分けのために、「ボタンを検知した」「送信した」「Discord の応答コード」をログに出すようにするのが最初の一手としておすすめです。来なかったときに、どこで止まったのかが分かります。

※ コードやログを共有するときは、Webhook の URL や Bot のトークンは伏せてください。
