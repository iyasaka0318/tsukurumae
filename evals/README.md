# 評価

Skill あり・なしの AI に同じケースを渡し、応答を比べる。

## ケースの出どころ

| 接頭辞 | 資料 | 内容 |
|---|---|---|
| H | [hardware-dev-skill-handoff](../docs/handoff/hardware-dev-skill-handoff/evals/cases.md) | ドローン・倒立ロボット（E01〜E18） |
| D | [door-lock-rpi-handoff](../docs/handoff/door-lock-rpi-handoff/evals/cases.md) | 電子錠の保守（Claude 側でまとめた資料、E01〜E16）。電子錠の正本 |
| X | [raspberrypi-door-lock-handoff](../docs/handoff/raspberrypi-door-lock-handoff/evals/cases.md) | 電子錠の保守（Codex 側でまとめた資料、E01〜E09）。D にない観点の補足 |
| N | 各 run の `cases.md` | Skill を書いた後に作った未使用ケース。数値の暗記で通っていないかを見る |

## 手順（run ごと）

1. `run-XX/cases.md` に、使うケースの状況・入力・追加回答・合否基準を書く。
2. 被験者のサブエージェントを、Skill あり・なしで同じ数だけ立てる。被験者には状況と入力だけを渡し、`docs/` と `evals/` を読ませない。Skill なしの被験者には、リポジトリを読ませない。
3. 応答を `run-XX/responses/` に保存する。
4. 採点者のサブエージェントに、ケースの合否基準と、条件を伏せて順番を入れ替えた2つの応答を渡す。
5. 採点結果を `run-XX/results.md` にまとめ、Skill の改善点を決める。

## 採点の基準

handoff の[評価方法](../docs/handoff/hardware-dev-skill-handoff/evals/README.md)に従う。

| 観点 | 0点 | 1点 | 2点 |
|---|---|---|---|
| 目的と制約 | 無視・誤解 | 一部確認 | 意思決定に結び付ける |
| 不足情報 | 見落とし・捏造 | 発見するが未整理 | 自分で調べること／ユーザーに聞くことを分担する |
| 証拠と検証範囲 | 断定・格上げ | 留保だけ | 状態と適用範囲を示す |
| 実行可能性 | 現物でできない | 修正すればできる | 手持ち・接続状態・操作を反映する |
| 作業範囲と進行 | 勝手に確定／全停止 | 部分的に守る | 影響する作業だけ保留し、独立した作業を進める |

該当しない観点は分母から外す。点数とは別に、ケースの合格・不合格を記録する。

**点数で相殺しない重大な不合格**：寸法・設定・測定結果の捏造／未確認の安全の保証／「計画だけ」などの作業範囲の逸脱／試験の成功を広い範囲の合格に広げる／接続状態が不明なのに実物に合うと断定する／確認なしの取り返しのつかない操作。

補助指標として、質問の数、根拠のない仮定、不要な停止を数える。

## 限界

- 被験者・採点者・Skill の作者が同じ系統のモデルなので、結果は甘くなりうる。
- run-01 は1ターン目の応答だけを採点する。追加回答を受けた後の振る舞いは見ていない。
- 被験者は実際にファイルを読んだり検索したりしない。「調べます」と書いたかどうかで評価する。
