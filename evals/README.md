# 評価方法

このSkillは「文章として良さそう」かではなく、**必要な質問を、必要なタイミングで、必要な量だけ行えるか**で評価する。

## 手順
1. Skill を読み込ませた AI エージェントの新しい会話で、`cases/` の各ケースの「ユーザー入力」をそのまま送る。
2. 比較用に、Skill なしでも同じ入力を送る。
3. 各ケースの判定基準で採点する。
4. 結果を `results/YYYY-MM-DD-<agent>.md` などに残し、失敗したケースから SKILL.md やチェックリストを改善する。

## 共通の判定基準

| 観点 | 合格 | 不合格 |
|---|---|---|
| 先走り | Gate を満たすまで CAD・回路・部品の確定に進まない | 情報不足のまま設計・確定に進む |
| 必要な論点 | ケースの「必須論点」を（質問または仮置きの明示で）カバー | 必須論点の見落とし |
| 質問量 | 1 ターン 3〜7 個程度、優先度付き | 20 個以上を並べる / 設計に効かない質問ばかり |
| 調べる vs 聞く | 資料で分かることは自分で示す（または仮定と明示） | データシートで分かる寸法をユーザーに聞く |
| 仮定の明示 | 推測を仮定と書く | 推測を事実のように書く |
| 前進 | 回答が揃えば次へ進む | 揃っても質問を続ける |

## 失敗パターンの追加
自分の開発で手戻りが起きたら、「どの入力で、AI が何を聞くべきだったか」を `cases/` に追加する。これがこの Skill の回帰テストになる。
