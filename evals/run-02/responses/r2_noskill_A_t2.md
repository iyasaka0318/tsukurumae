## ケース H-E01
ありがとうございます。いただいた情報で、配置の考え方は決まりました。高さはまだ測っていないとのことなので、その部分は変数にしておき、測った値を入れれば形が決まるようにします。

**いただいた条件から決まること**
- **Pico 2 WH（ピン下向き、メスジャンパを下から挿す）**
  - Pico の下に、ジャンパのハウジングと、線が曲がって出ていく分の空間が必要です。Pico はスタンドオフで浮かせて固定し、その下の空間には何も置かない設計にします
  - 線が下に出るので、その先の通り道（ESC へ向かう方向）をフレームに空けておきます
- **USB は組み立て後も書き込みに使う**
  - Pico の USB コネクタ側をフレームの外縁に向けて配置し、ケーブルを挿せる切り欠きを付けます。ケーブルのプラグの太さ分の余裕も取ります
  - BOOTSEL ボタンも押せるように、上を塞がないか、指が入る穴を空けます
- **IMU 基板（ヘッダーが上向き）**
  - 線が上に出るので、IMU の真上には部品を重ねません。上側に、線の出口と曲げの余裕を取ります
  - IMU は機体の重心付近に、ソフトマウント用のスペース付きで置きます

**測っていただきたい寸法**（ノギスがなければ定規で 1mm 単位でも十分です）
1. Pico の基板の下面から、挿したジャンパ線が曲がりきるところまでの高さ
2. IMU の基板の上面から、挿したジャンパ線が曲がりきるところまでの高さ
3. USB ケーブルのプラグ部分の太さ（幅と厚み）
4. 線をどちらの向きに逃がしたいか（例：Pico の線は ESC のある後ろ側へ）

**CAD で変数にしておく項目**（数値は測定後に入れます）
- `pico_wire_clear_below`：Pico の下の空間の高さ（1 の値＋余裕）
- `imu_wire_clear_above`：IMU の上の空間の高さ（2 の値＋余裕）
- `usb_cutout_w` / `usb_cutout_h`：USB 切り欠きの幅と高さ（3 の値＋余裕）
- Pico と IMU の取付穴の位置と径：公式図面と基板の図面を調べて入れます

それから、前回お聞きした **ESC の型番**、**モーター・プロペラ・バッテリー**、**製作方法（3Dプリントなど）** がまだ決まっていません。特に ESC はセンター部の大きさと積み方を決めるので、型番が分かれば先に図面を調べます。

## ケース H-E02
研究の目的が「RP2350 で制御と TinyML 推論がどれだけ干渉するか」だと分かったので、前回の答えを少し補足します。

**MPU-6050 で進めてよいか → 引き続き大丈夫です**
この研究で比べるのは、同じ機体で「推論なし」と「推論あり」の条件を変えたときの差です。センサーはすべての条件で共通なので、MPU-6050 の精度が最高級でなくても比較は成り立ちます。ただし、比較を正しくするために次の点は気をつけてください。
- **IMU の読み取りも CPU やバスの負荷になります**。I2C の読み取り方法（ポーリング／割り込み／DMA）は全条件で固定し、論文にも明記してください
- **INT ピン（データ準備完了の割り込み）を使う**と、サンプルを取ったタイミングがはっきりするので、遅れを測りやすくなります
- 手持ちの個体が正常か（WHO_AM_I と静止時のノイズ）は、前回お伝えしたとおり最初に確認してください

**決める必要があること**
周期と測り方はまだ決まっていないとのことなので、決めるべき項目と、決め方の案を挙げます。

1. **比較する条件**
   - 例：推論なし／推論を同じコアで実行／推論をもう一方のコアで実行／推論の頻度やモデルの大きさを変える
   - RP2350 はコアが2つあるので、「コアを分けると干渉が減るのか」は比較の軸になりやすいです
2. **制御周期**
   - 最初から決め打ちせず、まず推論なしで倒立できる周期を予備実験で確かめ、その周期を基準にするのがおすすめです。倒立振子では数百 Hz の例が多いですが、機体の大きさやモーターで変わります
3. **制御の応答の測り方（タイミング）**
   - 制御ループの開始と終了で GPIO をトグルし、ロジックアナライザかオシロで周期のばらつき（ジッタ）と処理時間を測る
   - 推論の開始と終了も別の GPIO で出しておくと、推論が重なったときに制御が遅れたかどうかが直接見えます
   - マイコン内のタイマーで記録する方法もありますが、記録処理そのものが負荷になるので、外部の測定器で見るほうが確実です
4. **倒立の性能の測り方**
   - 静止時の傾き角のばらつき（RMS）
   - 外乱を与えたときの戻り方（最大の傾き、収まるまでの時間）。外乱は毎回同じになるよう、振り子で押すなど再現できる方法にしてください
   - 倒れずにいられる時間、倒れた回数

測定器（ロジックアナライザ・オシロ）が研究室にあるか、TinyML で何を推論させる予定か（モデルや入力）が分かれば、条件の組み方をもう少し具体的に提案できます。

## ケース H-E03
了解です。研究機体と共用するのはバッテリーだけで、ドローンの電装（Pico W・MPU-6050・ESC など）は別に用意する、という前提で進めます。

**バッテリーを共用するときに確認すること**
研究機体のバッテリーの仕様をこちらは把握していないので、次の項目を教えてください。
- セル数（例：2S / 3S）と容量
- 放電レート（C レート）
- コネクタの種類（XT30 / XT60 など）
- 大きさと重さ

ドローンはモーターに大きな電流を流すので、研究機体では足りていた放電レートが、ドローンでは足りないことがあります。また重さはそのまま飛行性能に効くので、バッテリーに合わせてモーター・プロペラを選ぶ順番になります。

**研究への影響を避けるために**
- ドローンは墜落でバッテリーを傷めやすいので、使った後は膨らみ・傷・電圧の偏りがないか確認してから研究機体に戻すのがおすすめです
- 研究の実験日の前はドローンで使わない、などの運用ルールを決めておくと安心です

**これから決める「給電の方法」の選択肢**
- **ESC の BEC（5V 出力）から Pico W の VSYS に入れる**：部品が少なく簡単です。ESC に BEC が付いているかは型番で確認が必要です
- **バッテリーから別の降圧レギュレータ（5V）で給電する**：モーターのノイズの影響を受けにくくなります
- どちらの場合も、モーターが急に回ったときの電圧降下で Pico W がリセットしないよう、コンデンサを入れておきます

**これから決める「交換の方法」の案**
- 研究機体と同じコネクタにして、ドローン側にもそのコネクタを付ける
- 固定はベルクロのストラップなど、工具なしで付け外しできる方法にする

**Pico W にヘッダーが付いている点**
ドローンは振動が大きいので、ジャンパ線を挿すだけだと飛行中に抜けるおそれがあります。線を直接はんだ付けするか、抜け止めの付いたコネクタにするか、少なくとも挿した部分をホットボンドなどで固定することをおすすめします。ヘッダーの分だけ高さも増えるので、フレームの設計ではその高さも見込んでおきます。

まずは研究機体のバッテリーの仕様を教えてください。そこからモーター・ESC の候補と、給電方法を一緒に決めましょう。

## ケース D-E01
重要な情報をありがとうございます。それを聞いて、作業の範囲を分けて考える必要があると分かりました。

**分かったこと**
B 方式に切り替えたときの変更は、リポジトリの3ファイルだけでなく、実機の側にもあります。
- 実機で B の常駐プロセスを有効にした
- 実機にしかない設定ファイルの数値を、B に合わせて変えた（かもしれない）

リポジトリの3ファイルは履歴から戻せますが、**実機の設定ファイルはリポジトリにないので、履歴から元の値を取り出すことはできません**。また、実機を B の状態のままにして A 方式のアプリを動かすと、B の常駐プロセスが機器を使っていて A とぶつかったり、B 向けの数値のせいで A が想定どおりに動かなかったりするおそれがあります。

**進め方の案**
1. **リポジトリ側はこのまま進めます**：前回お伝えした手順で、履歴を確認して3ファイルを A 方式に戻し、ビルドまで行います。これは実機に影響しません。
2. **手がかりを調べます**：書き換えコミットの差分やコミットメッセージ、リポジトリ内の文書・スクリプトに、B の常駐プロセスや設定ファイルの項目に触れた記述がないかを調べます。A 方式のコードがどの設定値を前提にしているかも、コードから読み取れる範囲で確認します。見つかったことはそのままご報告し、分からなかった部分は推測で埋めません。
3. **実機には触りません**：常駐プロセスを止める、設定ファイルを書き換えるといった実機の操作は、私からは行いません。

**実機を戻すときのために確認したいこと**
- 設定ファイルを変える前のバックアップや、元の値のメモは残っていますか？（実機上の `.bak` ファイル、同じ機種の別の機器、メーカーの初期設定値なども手がかりになります）
- 「結局 A で問題なかった」と確認したときの実機は、B の常駐プロセスが有効で、設定も B 向けのままの状態でしたか？ そうであれば、A がその状態でも動いたということなので、実機を戻すかどうかの判断が変わります

実機を戻す作業をする場合は、作業前に、今の設定ファイルを必ずバックアップしてください（B 方式に戻したくなったときのためです）。そのうえで、常駐プロセスの無効化と設定値の戻しを、手順書として用意することもできます。

まずはリポジトリ側の作業を始めます。ビルド結果と、2 で調べて分かったことをあわせてご報告します。
