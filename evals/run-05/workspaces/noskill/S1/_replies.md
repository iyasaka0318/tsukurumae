## ターン 1

面白いテーマですね。RP2350 はデュアルコア（Cortex-M33 ×2、または RISC-V Hazard3 に切り替え可）なので、「姿勢制御ループと TinyML 推論を同じチップで回したときに、制御周期のジッタや遅れがどれだけ出るか」をきれいに測れる題材だと思います。

進める前に、いくつか先に決めておくと後で手戻りが少ない点があります。

**1. 「干渉」を何で測るか**
研究の成果がここで決まるので、最初に決めておきたいです。たとえば次のような指標が考えられます。
- 制御ループ周期のジッタ（目標周期からのずれの分布）
- IMU 読み取りからモーター出力までのレイテンシ
- 姿勢誤差（実際の飛行やテストスタンドでの角度追従）
- 推論側の遅延・スループットの低下

どれを主要な指標にするかで、ロギングの仕組みや計測用の GPIO トグルなどの準備が変わります。

**2. 構成の比較軸**
「同一コアで両方」「コア0 に制御・コア1 に推論」「割り込み優先度や DMA の使い方を変える」など、比べる条件をいくつ用意するかを決めておくと、ファームウェアの作りを最初から切り替え可能にできます。

**3. 実験の場所**
いきなり自由飛行で評価するより、ジンバル型のテストスタンド（1軸や3軸）に固定して測ると再現性が高く、機体を壊すリスクも下げられます。卒研の期間を考えると、「スタンドで定量評価 → 最後に飛行デモ」という流れが安全だと思います。

**4. MPU-6050 について**
手持ちがあるならまずは使い始めて大丈夫ですが、気になる点があります。
- MPU-6050 はメーカーではすでに生産終了（EOL）扱いで、市場に出回っているモジュールには互換品や偽物が多いです。個体によって特性がばらつくことがあります。
- I2C 接続（最大 400kHz）なので、高い制御周期で回すとバス転送の時間が無視できなくなります。干渉を調べる研究では、IMU 読み取り自体の時間が測定結果に混ざるので注意が必要です。
- モーター振動の影響を受けやすいので、防振マウントやデジタルローパスフィルタの設定が必要です。

研究の目的に対して十分かどうかは、目標の制御周期によります。SPI 接続の IMU（ICM-42688-P など）なら読み取りが速く、FIFO や割り込みも扱いやすいです。手持ちの MPU-6050 でプロトタイプを作り、必要になったら差し替えられるように IMU 部分を抽象化しておく、という手もあります。

**5. TinyML で何を推論するか**
推論タスク（例：振動からの異常検知、ジェスチャー、音声など）とモデルの規模で、計算負荷や RAM（RP2350 は 520KB SRAM）の使い方が大きく変わります。研究としては負荷を段階的に変えられるようにしておくと、「負荷と干渉の関係」が示せて説得力が増します。

## ターン 2

測りたいものが「制御周期の遅れ」と「姿勢の乱れ」なら、MPU-6050 を使うこと自体は、研究として致命的な弱点にはなりにくいと思います。研究の主題は「RP2350 上での処理の干渉」で、IMU の性能そのものではないからです。ただし、突っ込まれやすい点が3つあるので、先に手を打っておけば使い続けて大丈夫です。

**1. IMU の読み取り時間が「遅れ」に混ざる**
MPU-6050 は I2C（最大 400kHz）なので、加速度・ジャイロを読むだけで数百マイクロ秒程度かかる見込みです（実際の値は測って確かめます）。これが制御ループの中に入っていると、「その遅れは TinyML の干渉ではなく、I2C の待ち時間では？」と聞かれます。

対策：
- 読み取り開始・終了、制御計算、モーター出力の各時点で GPIO をトグルし、ロジックアナライザで区間ごとに時間を測る。
- 「TinyML なし」の条件を基準にして、TinyML ありとの差を干渉として示す。IMU の読み取り時間はどちらの条件でも同じなので、差を取れば IMU の影響は打ち消せます。
- I2C を DMA や割り込みで読むか、CPU で待つかも条件の一つになります。どちらにするかは先に決めて固定しておきます。

**2. 姿勢の乱れを、制御に使っている IMU 自身で測ると自己参照になる**
制御用 IMU の値で「姿勢が乱れた」と評価すると、IMU のノイズやドリフトと、本当の姿勢の乱れが区別できません。MPU-6050 に限らず、どの IMU でも同じ指摘を受けます。

対策：
- ジンバル型のテストスタンドに機体を載せ、軸にエンコーダー（ロータリーエンコーダーなど）を付けて、IMU とは別に真の角度を測る。
- それが難しければ、評価専用に別の IMU を載せる、または動画から角度を求める方法もあります。精度は落ちますが、独立した測り方であることが重要です。

**3. 個体の素性とノイズ**
MPU-6050 は生産終了品で、出回っているモジュールには互換品が多いです。「その IMU は本物か、特性はどうか」と聞かれたときに答えられるようにしておきます。

対策：
- 使ったモジュールの写真や刻印、購入元を記録しておく。
- 静止状態でしばらくデータを取り、ノイズやバイアスを測って論文に載せる（基礎データとして1節あると強いです）。
- モーター振動の影響を減らすための防振マウントとローパスフィルタの設定も記録しておく。

**判断のしかた**
次のどれかに当てはまったら、SPI 接続の IMU（ICM-42688-P など）に切り替えるのがよいと思います。
- 目標の制御周期に対して、I2C 読み取りが周期の大きな割合を占めてしまう（読み取り時間を測れば判断できます）
- 静止ノイズを測ったら、評価したい「姿勢の乱れ」と同じくらいの大きさだった
- 指導教員が IMU の選定を気にしている

最初の2つは、実際に MPU-6050 をつないで測れば1〜2日で確かめられます。IMU を読む部分を関数1つにまとめておけば、後から差し替えるときも制御や TinyML 側を書き直さずに済みます。

**おすすめの進め方**
1. RP2350 と MPU-6050 だけで、I2C 読み取り時間と静止ノイズを測る。
2. その結果と目標の制御周期を比べて、使い続けるか決める。
3. 指導教員に「主題は処理の干渉で、IMU の影響は差分と独立計測で切り分ける」という方針を一度見せておく。
