## ターン 1

いいですね。Next.js なら画面と API を一つのプロジェクトでまとめて作れるので、研究室規模のアプリには向いていると思います。

作り始める前に、いくつか確認させてください。ここが決まると、データ構造や認証の作りが固まります。

**使う人と運用**
1. 利用者は何人くらいですか？（研究室メンバーだけ？他の研究室や学生も使う？）
2. ログインは必要ですか？大学の Google アカウントなどでログインできると楽です。
3. 管理者（先生や機材担当）が予約を承認する流れは必要ですか？それとも先着で確定でよいですか？

**予約のルール**
4. 予約の単位は「時間帯（例：13:00〜15:00）」ですか？「日単位」ですか？
5. 1人あたりの上限や、予約できる期間（例：2週間先まで）などのルールはありますか？
6. 機材の数はおよそいくつですか？同じ機材が複数台ある（例：オシロスコープ3台）ケースはありますか？

**動かす場所**
7. どこで動かす予定ですか？（Vercel などのクラウド、研究室のサーバー、学内ネットワーク限定など）
8. 学外からアクセスできてもよいですか？

**その他**
9. 既存の予約方法（スプレッドシート、ホワイトボードなど）からデータを移す必要はありますか？
10. 通知（予約確定や前日のリマインドをメールや Slack に送る）は欲しいですか？

全部決まっていなくても大丈夫です。わかる範囲で教えてもらえれば、それを踏まえて「最小構成で作るもの」と「後から足すもの」に分けた計画と、技術構成の案（例：Next.js App Router ＋ データベース ＋ 認証）を出します。
