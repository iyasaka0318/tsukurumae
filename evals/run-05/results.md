## 分かったこと

- **目的から逆算した推奨が効いた。** S1 で Skill ありは、評価する人（指導教員・発表の聴衆）を挙げ、突っ込まれる点を5つ理由付きで先に出した。MPU-6050 は「CPU 側の干渉が主題なら交絡要因になる」「I2C を含めた現実の構成の研究なら筋が通る」と、目的によって結論が変わることを示し、決めるのはユーザーとした。Skill なしは、評価する人にも目的の確認にも触れなかった。
- **先に決まっていた技術を、目的に照らした。** S2 で Skill ありは、Next.js を「動かす場所との相性」「引き継ぐ人が読めるか」「そもそも作る必要があるか」で照らし、卒業後の保守・個人情報・止まったときの代わりを持ち出した。Skill なしは Next.js をそのまま受け入れ、構成案を出すと予告した。
- **記録・診断の計画を、要件定義の中で出した**（S1、S2）。
- **段階の表示は邪魔にならなかった。** 小さな依頼（S4）では付けなかった。
- **2ターン目の中身は、Skill なしも追いついた**（S1）。差は、1ターン目で先に言えるかどうかに出た。
