# tsukurumae（つくるまえ）

始める前に、目的から、何をどう進めるかを AI と一緒に考えて決める Agent Skill。Claude Code と Codex で使う。
ハードウェア（ドローン、ロボット、電装、3D プリント、CAD）やソフトウェア（ファームウェア、アプリ、スクリプト、解析）の開発・改修に加え、研究や卒論の計画、調査、企画など、作るものがない場面でも使う。

**使うとどうなるか**
- **AI が、あなたの目的から逆算して、提案や改善案を出してくる。** あなたが考えていなかった方向や、計画を変える案も含む。
- その土台として、分からないまま進めることと、「そういうつもりじゃなかった」が減る。
- そのぶん、最初に聞かれる数は多くなる。
- 結果として、手戻りが減って楽になることもある。

> 開発中（第5版）。最初はサブエージェントによる比較評価（[run-01](evals/run-01/results.md)〜[run-05](evals/run-05/results.md)、第1〜3版が対象）で形を作り、今は実際の案件（卒研の倒立振子ロボット、個人用の音声依頼ツールの改修など）で使いながら直している。

## 使い方

```
/tsukurumae ドローン作ろうと思ってる。計画はこれ（資料があれば添付）
/tsukurumae 卒論の計画を立てたい
/tsukurumae 動いているこのツールに機能を足したい
/tsukurumae 見直して
```

Codex では `$tsukurumae`。

1. **方針を決める（この Skill）**：AI が目的と現状を捉え、目的をよりよく実現する方向を、あなたが考えていなかったものも含めて提案する。判断の軸も目的から立てる。開いた質問で方針を一緒に決める。合意するまで、コード・CAD・章立てなどの成果物は作らない。
2. **合意したら、決めたことを残す。** 形は案件に合わせる（下の表）。
3. **作業は新しい会話で始める。** Claude Code も Codex も `CLAUDE.md` / `AGENTS.md` を自動で読むので、`/tsukurumae` なしで指示書に従って進む。案を作ったり重要な判断をしたりする前に、作業する AI も目的に立ち返る。
4. **方針を変えたいときは** `/tsukurumae 見直して` で、残した文書を読み直して更新する。

### AI がすること（考え方の要点）

決まった手順や確認項目ではなく、次の考え方で動く。詳しくは [SKILL.md](skills/tsukurumae/SKILL.md)。

- **目的を一緒に言葉にする。** どこに重みがあるか（目指す水準、必須の条件、補助的な価値）まで、最初の提案の前に確かめる。作ること自体が楽しい、という目的も大切にする。
- **目的から、何をするとよいかを考える。** 依頼されたものや、既に決まった設計・部品・今ある機能を、考える枠にしない。改修でも、まだないものを考える。失敗を避けるだけでなく、目指す水準に届く方向を先に考える。
- **案を目的に照らしてから出す。** 採用したら目的の達成がどう変わるかを、今の方針と比べる。足す案は組み合わせた状態で考える。効果が未確認の案も、理由と不確かな点を示して出してよい。
- **判断の軸も目的から立てる。** 整って見えることや進めやすさだけで選ばない。比べられることは AI が比べて、推奨と理由を示す。決めるのはあなた。
- **反対ははっきり一度だけ。** あなたが「それでいい」と決めたら、新しい事実が出ない限り繰り返さない。
- **確かめていないことを事実として書かない。** 記憶や README の記述も「確認していない」と明記し、調べられることは元を調べる。

### 残るもの

| ファイル | いつ作るか | 誰が読むか |
|---|---|---|
| `TSUKURUMAE_REQUIREMENTS.md`（要件定義書） | 開発の案件。研究計画や企画なら、その計画書そのものに書く | あなた |
| `TSUKURUMAE_GUIDE.md`（案件専用の指示書） | 別の会話で作業が続くとき | 作業する AI |
| `CLAUDE.md` / `AGENTS.md` に1行 | 指示書を作ったとき | 作業する AI（自動で読む） |

指示書には、目的、優先することと理由、決めたこと、まだ分かっていないこと（確かめ方と、確かめるまでやらないこと）、進め方と今の段階、作業中の注意が入る。次の注意は、どの案件の指示書にも毎回入る。

- 案を作ったり重要な判断をしたりする前に、目的に立ち返る。
- 資料（型番、データシートなど）で分かることは AI が調べ、現物でしか分からないことだけをあなたに頼む。
- 計算や確認をしていない数字は「見込み」「仮」と書く。

## インストール

### プラグインとして入れる（おすすめ）

各マシンで1回だけ実行する。Skill を直して push したら、更新コマンドで反映される。
手でコピーした `~/.claude/skills/tsukurumae` が残っていると、古い版が読まれることがある。プラグインに切り替えたら消す。

```bash
# Claude Code
claude plugin marketplace add iyasaka0318/tsukurumae
claude plugin install tsukurumae@tsukurumae
# 更新
claude plugin update tsukurumae@tsukurumae
```

```bash
# Codex（未確認。読み込めなければ下の「手でコピー」を使う）
codex plugin marketplace add iyasaka0318/tsukurumae --ref main
codex plugin add tsukurumae@tsukurumae
```

プラグインとして入れると、呼び出しが `/tsukurumae:tsukurumae` になる場合がある（未確認）。

### 手でコピーする

```bash
# Claude Code（全プロジェクト）
cp -r skills/tsukurumae ~/.claude/skills/
# Codex（全プロジェクト）
cp -r skills/tsukurumae ~/.agents/skills/
```

クラウドのセッションでは、ユーザー設定のプラグインが引き継がれないことがある。クラウドで使うプロジェクトでは、そのリポジトリの `.claude/skills/tsukurumae/`（Codex は `.agents/skills/tsukurumae/`）に置く。

    materials/                指示書を作るときに選んで使う材料（証拠、確定条件、ハード・ソフト・研究の観点、過去の手戻り）

## 使いながら直す

1. **記録**：Skill を使っている間に、あなたが AI の振る舞いを直すと（「違う」「先に聞いて」など）、AI がそのプロジェクトの `TSUKURUMAE_FEEDBACK.md` に自動で記録する。頼む必要はない。
2. **送る**：案件の会話で「作る前用のフィードバック作って」と言うと、AI がその案件での使われ方（目的、出した提案、あなたの感想、直された記録）を要約し、PC の tsukurumae の clone（既定：ホームの `.claude/tsukurumae-repo`。なければ clone する）の `feedback/inbox/` に書いて push する。方針を決めた会話と作業の会話が別なら、両方で送ると経緯まで残る。
3. **反映**：このリポジトリの会話で、届いたフィードバックを仕分けて Skill に反映する。手順は [feedback/README.md](feedback/README.md)。手で貼って「フィードバック取り込んで」と言ってもよい。

記録の仕組みは開発中だけのもの。Skill が安定したら、`SKILL.md` の「改善用の記録」の節を消せば止まる。
