# Step 2：システム設計・開発計画

## 目的
Step 1 の要求を満たすために**どういうシステムを作るか**を決め、システム全体として成立していることを確認する。細かな CAD 形状はまだ作らない。

## 手順

### 2-1. 構成ブロックを洗い出す
必要に応じて:
- 制御：MCU、センサ、ソフトウェア構成、制御周期
- 駆動：モータ、ESC/モータドライバ、プロペラ/ホイール/ギア
- 電源：バッテリー（電圧・セル数・容量・放電レート）、レギュレータ（5V/3.3V）、電源スイッチ、保護
- 通信：無線方式、帯域、遅延、デバッグ用シリアル
- 機構：フレーム、マウント、可動部
- 開発環境：工具、消耗品、測定器

ブロック図（テキストで可）で信号と電源の流れを示す。

### 2-2. 部品を「必要十分」で選ぶ
基本方針：**目的に対して必要十分な性能を確保し、不必要なコストは掛けない。**

判断が分かれる部品は、必要に応じて 2〜3 案を比較する:

| 案 | 部品 | 価格 | 性能 | リスク | 拡張性 | 目的（研究等）への妥当性 |
|---|---|---|---|---|---|---|
| 最安案 | | | | | | |
| 必要十分案 | | | | | | |
| 余裕案 | | | | | | |

- 推奨案とその理由を明示する。
- 価格・在庫・リンクは変動するため、調べた日付や「要確認」を付ける。調べられない環境なら推定値と明示する。
- 「この部品は最終目的に対して本当に十分か」を、成功条件に照らして一文で書く。

### 2-3. 成立性を数値で確認する（概算でよい）
該当するものを確認する。計算は式と前提値を見せる。

| 項目 | 確認内容 |
|---|---|
| 重量 | 部品重量の合計＋配線・フレーム・ネジの見込み（未知分はマージン 10〜20%） |
| 推力/駆動力 | ドローン：総推力 / 重量 ≥ 2 程度が目安。倒立振子：必要トルク・応答 |
| 電力・飛行/稼働時間 | 平均・最大電流、容量から稼働時間の概算 |
| ESC/ドライバ定格 | モータ最大電流に対する余裕 |
| レギュレータ | 5V/3.3V 系の合計電流と許容電流、発熱（リニアなら損失 = 電圧差 × 電流） |
| 電圧レベル | バッテリー電圧の範囲（満充電〜終止）と各部品の入力範囲、ロジックレベル（3.3V/5V）の整合 |
| I/O | PWM・I2C/SPI・UART・ADC の必要数と MCU の割り当て可能数、ピンの競合 |
| センサ性能 | ノイズ、レンジ、サンプリングレート、インタフェース速度が成功条件に足りるか |
| 通信 | 帯域・遅延・距離 |
| サイズ | 主要部品が目標サイズに物理的に収まるか（概略レベル） |
| 予算 | 総額と予備（壊れやすい部品：プロペラ、ESC、IMU など） |

### 2-4. 電装は聞かれなくても扱う
ユーザーが電装に詳しくない前提で、必要なら AI 側から以下を検討・質問する:
バッテリー電圧とセル数、ESC 定格、5V/3.3V 系の作り方、電流容量、コネクタ（XT30/XT60/JST 等）、配線の太さ、信号電圧、GND の取り方（共通 GND、ループ）、モータノイズ、電圧降下（ブラウンアウトによる MCU リセット）、発熱、フェイルセーフ（通信断・低電圧時の挙動）、電源投入順序、逆接続保護。

### 2-5. 開発計画
- 購入品リスト（BOM の素案）：部品、数量、価格、手持ちか購入か、代替候補
- 必要な工具・消耗品
- 開発順序：リスクの高いもの・納期の長いものから。可能なら「ベンチテスト（机上で通電・センサ読み取り）→ 部分組立 → 全体」の順。

## Gate 2 チェック
- [ ] ブロック図で電源・信号の流れが閉じている
- [ ] 重量・推力（駆動力）・電力・稼働時間の概算で致命的な問題がない
- [ ] 電圧レベルとレギュレータ容量に問題がない
- [ ] I/O 数とインタフェースが足りる
- [ ] 主要センサが成功条件に対して十分（理由を説明できる）
- [ ] 予算内、または超過をユーザーが了承
- [ ] 主要部品をユーザーと決定（Decided）した
