# 要件定義書の書式

プロジェクトのルートに `TSUKURUMAE_REQUIREMENTS.md` として置く。要件定義の段階の終わりに、ユーザーの OK をもらってから書く。
短く保つ。1画面〜2画面に収まる程度にする。細かい値や経過は台帳に書く。

```markdown
# <プロジェクト名> 要件定義
合意日: YYYY-MM-DD

## 目的
- （ユーザーが確かめた言葉で）

## 種類
- ハード / ソフト / 両方、ゼロから / 改修

## 成功条件
- 何ができたら完成か

## 評価する人
- 誰が、何を見て評価するか（研究なら教授・学会の聴衆、など）

## 既に決めていたものの確認
| 決めていたもの | 目的に照らした結果 | どうしたか |
|---|---|---|
| | 足りる / 足りない（理由） | そのまま / 変更 / リスクを承知で維持 |

## 方針（決めたこと）
| 分野 | 方針 | 理由 |
|---|---|---|
| 電源 | | |

## 制約
- 予算、期限、大きさ、使う場所、手持ちなど

## リスクを承知で決めたこと
| 内容 | AI が伝えたリスク | 決めた理由 |
|---|---|---|

## 後で決めるもの
| 項目 | 誰が後回しにしたか（ユーザー / AI） | いつ決めるか |
|---|---|---|

## 記録・診断の計画
| 何が分からない・見えないか | 何を記録・診断するか |
|---|---|

## 頼んだ実測
| 何を | どこからどこまで | 使う場面 |
|---|---|---|
```

要件を変えたときは、変えた日と理由を末尾に1行で残す。
