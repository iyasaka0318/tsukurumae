# Step 1：要求定義・前提監査

## 目的
「何を作るのか」を正しく定義する。この段階では部品の確定・CAD・コード生成に進まない。

## 手順

### 1-1. 既に与えられた情報を整理する
ユーザーの最初の発言から、目的・確定事項・使いたい部品・制約らしきものを抜き出し、台帳の分類に振り分ける。
この時点で「ユーザーが言ったこと」と「AI が推測したこと」を分ける。

### 1-2. 不足している観点を選ぶ
以下は**全部聞くためのリストではなく、選ぶためのリスト**。目的と回答内容から、今必要なものだけを選ぶ。

| 観点 | 典型的な質問 | 何に効くか |
|---|---|---|
| 目的 | 研究・趣味・学習・実用品のどれか。研究なら何を評価・測定したいか | 性能要求、部品のグレード |
| 成功条件 | 何ができたら完成か（「30秒ホバリング」「姿勢角を±1°で保持」など、できれば測れる形で） | 性能要求、Gate 判定基準 |
| 既に決まっているもの | 変える気のない部品・方式 | 確定事項 |
| 手持ち部品 | 型番・状態（ヘッダー付きか等） | 予算、Step 3 |
| 予算 | 総額の目安、上振れ許容幅 | 部品案の幅 |
| サイズ・重量 | 上限や目標 | 成立性 |
| 性能要求 | 制御周期、精度、飛行時間、負荷など | 部品選定 |
| 期限 | いつまでに何を | 選択肢の現実性（納期など） |
| 設備 | 3D プリンタ（造形サイズ・材料）、はんだごて、テスタ、オシロ、電源装置、CAD ソフト | 設計方式、組立方法 |
| スキル・不安 | 電装・はんだ付け・制御・CAD のどこに自信がないか | 説明の深さ、AI が先回りすべき範囲 |
| 安全・運用 | 屋内/屋外、人の近くで動かすか、法規（ドローンなら重量・飛行場所） | 制約、フェイルセーフ |

### 1-3. 曖昧な言葉の意図を確認する
特に以下の言葉は、そのまま固定せず優先順位を確認する。

| ユーザーの言葉 | 確認すべきこと |
|---|---|
| 安くしたい | 安さ最優先か / 必要性能を満たした上で安くか / 研究上意味があれば多少高くてもよいか / 許容できる差額 |
| 小さく・軽く | 目標値はあるか / 何のためか（飛行時間？携帯性？規制？）/ 整備性とのトレードオフ |
| 高性能 | どの性能か（精度・応答・耐久・ノイズ）/ 何と比べて |
| とりあえず動けばいい | 次の段階（研究・発展）で作り直しになっても良いか |
| 簡単に作りたい | はんだ付けを避けたいか / 配線を減らしたいか / 部品点数を減らしたいか |
| この部品を使いたい | 理由（手持ち？評判？指定？）/ 目的に対して十分か |

### 1-4. 矛盾とリスクを指摘する
例:
- 「250g 未満」かつ「1 時間飛行」→ 同時に成立しにくい
- 「研究で姿勢推定の精度を評価したい」かつ「最安 IMU」→ センサノイズ・ドリフトが研究の評価対象を汚す可能性
- 「屋外で使う」かつ防水・防塵の検討なし

指摘には理由と代替案（目標値の緩和、優先順位の確認）を添える。

## Step 1 終了時に整理されているべきもの
- 目的
- 成功条件（できれば測定可能な形）
- 確定事項 / 仮決定事項 / 未決定事項 / 不明事項
- 制約（予算・重量・サイズ・電源・設備・期限）
- 優先順位（価格・性能・研究上の妥当性・作りやすさ・耐久性 …）
- リスク
- 矛盾

## Gate 1 チェック
- [ ] 目的と成功条件をユーザーと合意した
- [ ] 優先順位が分かっている（特に「価格 vs 性能」）
- [ ] 制約の主要な値（予算・サイズ/重量の目安）がある、または仮置きを合意した
- [ ] 重大な矛盾が解消された、または意図的に受け入れた
- [ ] 残る未決定事項は Step 2 で決めればよいものだけ
