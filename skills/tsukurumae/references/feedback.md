# 改善用の記録

tsukurumae 自体を改善するための記録。ユーザーが AI の振る舞いを直したときに、AI が自分から残す。
普段の作業を遅くしないことを優先する。確認や質問はせず、短く書いて、作業を続ける。

## 置き場所

- プロジェクトのルートの `TSUKURUMAE_FEEDBACK.md` に追記する。なければ作る。
- 指示書（`TSUKURUMAE_GUIDE.md`）とは別のファイルにする。指示書はそのプロジェクトのため、この記録は tsukurumae のためのもの。
- ファイルを書けない環境では、応答の末尾に同じ書式で記録を示す。

## 記録するとき

- ユーザーが AI の振る舞いを直した。例：「違う」「そうじゃない」「先に聞いてよ」「勝手に作るな」「なんで〜しなかったの」「〜してほしかった」。
- AI の思い込みや見落としが原因の手戻りが分かった（ユーザーが指摘していなくても）。
- ユーザーが「これ記録して」「フィードバックに入れて」と言った。

## 記録しないとき

- ユーザーが方針・好み・優先順位を変えただけで、AI の振る舞いに問題がないとき。
- 実際に動かさないと分からなかった問題で、AI が事前にできることがなかったとき。ただし、迷ったら記録する。

## 書式

1件を5行程度にする。

```markdown
## YYYY-MM-DD <短い題>
- 状況：何をしていたか（1行）
- AI がしたこと：
- ユーザーの指摘：（発言の要点。原文が短ければそのまま）
- 本当はどうしてほしかったか：（ユーザーが言っていなければ「推測：」と付ける）
- 関係しそうなルール：（SKILL.md の原則や確定条件。なければ「新しい」）
```

## 注意

- トークン、パスワード、個人情報、社外秘の値は書かない。必要なら種類だけ書く。
- 記録したら、応答の最後に1行だけ伝える。例：「（改善用に `TSUKURUMAE_FEEDBACK.md` に記録しました）」
- 記録のために作業を止めない。記録の内容をユーザーに確認しない。
- プロジェクトのリポジトリに入れたくない場合は、ユーザーが `.gitignore` に `TSUKURUMAE_FEEDBACK.md` を足せばよい。

## フィードバックを送る

ユーザーが「作る前用のフィードバック作って」「tsukurumae のフィードバック送って」と言ったら、この案件での tsukurumae の使われ方を要約して、tsukurumae のリポジトリに上げる。ユーザーにファイルを渡させない。

方針を決めた会話と作業の会話が別なら、方針を決めた会話の終わりにも送るとよい。取り下げた案の経緯やユーザーの反応は、その会話でしか拾えない。

### 送り先

- tsukurumae のリポジトリの clone。既定の場所はホームフォルダーの `.claude/tsukurumae-repo`。
  - Windows：`%USERPROFILE%\.claude\tsukurumae-repo`
  - WSL から：`/mnt/c/Users/<Windows のユーザー名>/.claude/tsukurumae-repo`
  - Linux・Mac：`~/.claude/tsukurumae-repo`
- 見つからなければ、既定の場所に `git clone https://github.com/iyasaka0318/tsukurumae.git` する。
- clone で Git の名前とメールアドレスが未設定なら、commit の前にユーザーに伝え、ユーザーが決めた値をその clone だけに設定する（`git config user.name` / `user.email`、`--global` は使わない）。
- 書くファイル：`feedback/inbox/YYYY-MM-DD-<案件名>.md`。同じ案件のファイルが既にあれば、末尾に追記する。

### 中身

全文を写さず、tsukurumae の改善に要るところだけを要約する。

```markdown
# <案件名>（<今の段階>まで）

## 案件の要点
- 目的：
- 種類：ハード／ソフト、ゼロから／改修、作ること自体が目的か
- 今の段階：

## tsukurumae がしたこと
- 検討した方向と、選んだ範囲：（AI から出した方向と、取り下げたもの）
- ユーザーが考えていなかったと思われる提案：
- 確かめずに残したこと、読まずに進めたもの：

## ユーザーの感想
- （会話から拾う。拾えなければ「考えていなかった提案はあったか」「足りなかった提案はあったか」を聞く。聞くのはこの2問まで）

## 直された記録
- （`TSUKURUMAE_FEEDBACK.md` の項目を、そのまま写す）

## AI が気づいたこと（ユーザー未確認）
- （Skill の書き方が原因に見えるところ）
```

### 上げ方

1. clone に未コミットの変更がないか確かめる。あれば、触らずにユーザーに伝える。
2. `git pull` して最新にする。
3. ファイルを書き、そのファイルだけを `git add` して commit し、push する。
4. 書いたファイルの場所と commit を1行で伝える。

### 注意

- 秘密情報（トークン、鍵、パスワード）を書かない。
- ユーザー名が入ったパスは伏せる（例：`<ユーザーのPC>\Documents\...`）。
- push に失敗したら、無理に直さず、何が起きたかを伝える。ファイルは clone に残しておく。
