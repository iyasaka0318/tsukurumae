# 手戻りカタログ

実際の開発で起きた手戻りを、ほかの案件にも当てはまる形にまとめたもの。具体的な数値は例であり、覚えるものではない。
出典の ID（F01 など）は、リポジトリの `docs/handoff/` にある実例資料を指す。

## 要求と選定

### 局所的な条件だけで選ぶ（F01、F04）
- 起きたこと：「安く」を価格だけの条件として扱うと、研究に必要な性能や、実際の総額（数量、送料、周辺回路）の確認が遅れる。
- 防ぎ方：目的から必要な仕様を導き、それを満たす候補を総額で比べる。逆に、必要以上に高い候補へ寄せない。

### 用途の変更を見逃す（E03）
- 起きたこと：研究用とは別に趣味用を作るとき、研究用の制約をそのまま持ち込みそうになる。
- 防ぎ方：用途が変わったことを確かめ、共有するもの（例：電池だけ）を確認する。用途の変更を「前の要求への違反」と扱わない。

### 資料の提案をそのまま採用する（R01）
- 起きたこと：別 AI のレビューが、平均電圧だけを根拠に回路を省く案を出した。
- 防ぎ方：ピーク、満充電、回生、遮断の条件と、メーカーの許容範囲を照らす。根拠がなければ採用しない。

## 物理的な実装

### 部品単体の寸法で設計する（F02、F03）
- 起きたこと：基板と穴は合ったが、挿すコネクターのハウジングが入らなかった。上向きのピンにコネクターを挿すと、高さが大幅に増えた。
- 防ぎ方：接続した後の占有範囲（ハウジング、線の曲げ、抜き差し、調整の空間）を確定条件に入れる。分からないうちは試験片で確かめ、本番の適合は未確認にする。

### 隙間を広げて解決したつもりになる（F02）
- 起きたこと：入らないスリットを広げたら、入ったが緩くなり、隣の穴の周りが薄くなって変形しかけた。
- 防ぎ方：何が緩いのかを確かめる。合っている寸法は維持し、幅と支持の形を別々に試す。

### 運用の変更が他の場所に波及する（R03、R04）
- 起きたこと：ログを USB で回収する運用にしたら、プラグと電池の台が干渉する可能性が出た。運用を変えた後も古い前提の説明が残った。
- 防ぎ方：運用を変えたら、それに依存する空間・配線・手順・説明を探して更新する。

## 証拠と検証

### 推奨値を合格値として扱う（F05）
- 起きたこと：本番用の推奨穴径を、試験で合った値のように列挙した。写真だけで原因を断定した。
- 防ぎ方：値に状態（実測、推奨、推定）を付ける。観察と診断を分ける。

### テスト合格を実機の動作と混同する（F07）
- 起きたこと：ファームウェアはビルドとホストのテストに通ったが、指令の上限が相手機器の始動する範囲に届いておらず、実機では回らなかった。
- 防ぎ方：指令の値を相手の仕様と照らす。実機で失敗したら、操作・配線・電源・指令の仮説を切り分け、AI 側の生成物も疑う。

### 成功の範囲を広げる（F10）
- 起きたこと：回転したという報告と短い「おｋ」から、停止・固定・推力まで確認済みとしかねなかった。
- 防ぎ方：試験した範囲だけを合格にする。固定の対象を分けて確かめる。

### 結果が記録に残らない（F09）
- 起きたこと：試作の結果を会話では受け取ったが、次の設計が参照する記録に書かれていなかった。
- 防ぎ方：受け取った時点で記録に書く（指示書の記録の欄など）。

## 手順と操作

### 本人が実行できない説明（F06）
- 起きたこと：用語や電気的な意味は正しいが、手持ちの部品で何をすればよいか分からなかった。
- 防ぎ方：操作として書く（何をどこに挿し、どうすると止まるか）。設定は再現できるファイルで渡す。

### 使えない測定点を指定する（F08）
- 起きたこと：測定の基準に指定した端子が、給電の配線で埋まっていた。
- 防ぎ方：今の接続状態で空いている同等の端子を、ピン配置で確かめて指定する。

## 残すべき良い行動

反省を理由に、次の行動まで禁止しない。

- 報告された「緩い」が何を指すのかを確かめた。
- 「電源を共通にしたい」が、電池だけのことだと確かめた。
- 本番の設計の前に、寸法を調べる試験片から始めた。
- 「計画だけ」の指示に従い、CAD を変更しなかった。
- メーカーの範囲を根拠に、平均値だけで判断する案を見送った。

## ソフトウェア（電子錠の保守より。出典 ID の D は `door-lock-rpi-handoff`、X は `raspberrypi-door-lock-handoff`）

### リポジトリの外の変更を見落として元に戻す（D-F01）
- 起きたこと：コードを元の方式に戻したが、以前の方式のために実機で有効にした常駐プロセスと、実機にだけある設定値が残っていて、何も動かなくなった。
- 防ぎ方：戻す前に、その変更に付随して実機側で変えたものを確かめる。記憶が曖昧なら、見るコマンドを先に出す。戻す前に今の状態を保存する。

### 古いログや1件の相関を原因にする（D-F02、D-F07）
- 起きたこと：4か月前の1件のクラッシュを今回の原因として報告した。電源断の直後に1回フリーズしたことから、定期的な電源断を有害として削除した。
- 防ぎ方：今の障害の観測と一致するまで候補にとどめる。同じログの中の反例（電源断と無関係に起きているフリーズ）も探す。

### 本番と違う条件で再現する（D-F03、X-F05）
- 起きたこと：サービスは root で動くのに、`sudo` なしのコマンドで再現を試み、結果を誤読した。サービスの再起動を OS の再起動と取り違えかけた。
- 防ぎ方：実行ユーザー、作業ディレクトリ、環境変数を揃える。似た現象は、それぞれを確かめるコマンドで区別する。

### 実行場所の分からないコマンド（D-F04、X-F06）
- 起きたこと：`curl localhost` を、どのマシンで実行するか書かずに渡し、ユーザーが Windows の PowerShell で実行して止まった。複数のコマンドを1つの塊で渡し、一部だけ実行された。
- 防ぎ方：実行するマシンと端末を書き、1つずつ貼れる単位で出す。

### 検知できない故障の保険を消す（D-F07）
- 起きたこと：無駄に見えた定期的な電源断を消したら、検知できない種類の故障で2日半無反応になった。
- 防ぎ方：保険が拾っている故障を確かめる。消すなら、切り替え可能にし、戻す条件を先に決める。

### 実害のない問題を直して、復旧経路を塞ぐ（D-F11）
- 起きたこと：二重に開かれるが実害のない現象を、ロックと「接続済みなら見送る」条件で直したら、固まったときの復旧経路が塞がれ、40分停止した。
- 防ぎ方：実害がなければ直さない。直すなら、1か所が固まっても別の経路が復旧することと、待ちに上限があることを確かめる。

### 失敗を値に変える呼び出し先を見落とす（D-F08）
- 起きたこと：呼び出し先が通信エラーを `null` に変えて返すのに、戻ってきたこと自体を「生きている」と判定し、USB を抜いても検知しなかった。
- 防ぎ方：失敗の返し方を読み、成功を示す戻り値のときだけ判定を更新する。

### 頼まれていない追加を混ぜる（D-F06、D-F05）
- 起きたこと：診断した原因への修正に、監視や自動電源断などの追加を同時に入れた。調査用の詳細ログを既定で出し、運用中のログを埋めた。
- 防ぎ方：追加は提案として分ける。ログの量を見積もり、既定では抑制する。

### 関係のないファイルをコミットする（D-F10）
- 起きたこと：`git add -A` で、ユーザーが別に入れたファイルを巻き込んで push した。
- 防ぎ方：変更したファイルだけを個別に stage し、差分を確認してからコミットする。

### 外部仕様の変更を記憶で原因にする（D-F12）
- 起きたこと：外部サービスの仕様変更を、一次情報で確かめずに原因として述べた。チャットと資料で確信度の書き方が違った。
- 防ぎ方：一次情報で確かめるか、確かめていないと書く。確信度をそろえる。

### ビルド成功や画面の表示を動作の証拠にする（X-F01、X-F03）
- 起きたこと：ビルド成功の後、実機ではライブラリの初期化に失敗していた。USB の一覧に見えても、カードの入力はアプリに届いていなかった。画面では開錠でも、モーターは動いていなかった。
- 防ぎ方：層を分けて観測し、確認した層までを報告する。

## 残すべき良い行動（ソフトウェア）

- 判断が分かれる所だけを、選択肢付きで質問した（D-G01）。
- 元に戻す前に、今の状態をコミットした（D-G02）。
- 本番機への操作は自分で実行せず、手順を渡した（D-G03）。
- 共有・コミットの前に、秘密情報を検索した（D-G04）。
- 依存関係の解決結果やバイトコードなどの一次情報で、原因を確定した（D-G05）。
- 反論を受けて主張を撤回し、直接の証拠を取りに行った（D-G06）。
- 推測を、基準値と当たり外れの条件を持つ実験にした（D-G07）。
- 自分の誤りを、指摘される前に開示した（D-G08）。
- 失敗の後、手順を規則として文書にした（D-G12）。
