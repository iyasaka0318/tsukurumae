# 残したい良い行動

## G01 — 変更前に目的と作業境界を明示
- **証拠**：[C009](../sources/conversation.md#c009)、[C025](../sources/conversation.md#c025)
- **行動**：ユーザーは復元理由を説明してからコード変更前の相談を求めた。鍵側は自分、Discord botは後輩に依頼する範囲とした。
- **残す理由**：相談を実装許可と誤解せず、責任範囲・優先順位に合わせる。
- **評価**：E02

## G02 — 安全と緊急度を共有
- **証拠**：[C006](../sources/conversation.md#c006)、[C021](../sources/conversation.md#c021)
- **行動**：その場は無人で内側から退出可能、FeliCa不調は人がUSB抜き差しで復旧する運用と説明。
- **残す理由**：リスクを理解して変更の緊急度を調整できる。
- **評価**：E02、E04

## G03 — 観測を順番に追加する
- **証拠**：[C010–C020](../sources/conversation.md#c010)
- **行動**：systemd、unit、起動スクリプト、ログ、例外、HTTP、GPIO設定を順に共有し、現象の変化も報告。
- **残す理由**：プロセス停止、native GPIO、Web応答、実モータを別問題として更新できる。
- **評価**：E01、E07

## G04 — 低コストの測定のみを選び、データを待つ
- **証拠**：[C030–C032](../sources/conversation.md#c030)
- **行動**：sendCommand時間の記録だけを行い、即時修正はせず数日後に比較すると指定。後日ログを共有。
- **残す理由**：不確かな原因に大きな変更を入れず、仮説検証データを得る。
- **評価**：E03

## G05 — 証拠を追加し、誤解を訂正
- **証拠**：[C028–C041](../sources/conversation.md#c028)
- **行動**：複数日ログ、journalctl、プロセス一覧を提示し、「二回再起動」の前提も訂正した。
- **残す理由**：仮説に固執せず、観測可能な事実へ更新する。
- **評価**：E05

## G06 — ログを使った長期観察
- **証拠**：[C032–C039](../sources/conversation.md#c032)
- **行動**：logrotateを設定し、freeze/reopen/poll統計やクラッシュ記録を日をまたいで収集。
- **残す理由**：断続故障を一回の再起動後の印象だけで判断しない。
- **評価**：E03、E04
