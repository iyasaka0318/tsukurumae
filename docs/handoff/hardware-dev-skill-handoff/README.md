最初に[要件整理](docs/REQUIREMENTS.md)と[失敗分析](examples/drone-failures.md)を読む。このフォルダーは別チャットでSkillを開発するための資料であり、Skill本体ではない。`SKILL.md`、インストール、公開、既存エージェントの設定変更は行っていない。

対象の会話は「ドローンフレーム設計を確認」。2026-09-14〜2026-10-06の過去84ターンを取得し、ユーザー発言86件とAIの進捗・回答191件を保存した。現在の引継ぎ資料作成ターンは含めない。

## 読む順序

1. [要件整理](docs/REQUIREMENTS.md)：ユーザーが目指すもの、対象、避けたい振る舞い。
2. [ドローン等の失敗分析](examples/drone-failures.md)と[倒立ロボットのレビュー経緯](examples/inverted-pendulum.md)：原因、影響、改善候補、元発言へのリンク。
3. [評価ケース](evals/cases.md)と[評価方法](evals/README.md)：将来のSkillを試す入力と期待行動。

## 証拠の読み方

`Cxxx`は会話ターン、`Fxx`は失敗分析、`Rxx`は研究側レビュー、`Exx`は評価ケースの識別子。取得した元発言、保存済み資料、今回の分析を区別する。ソース資料の対応は[sources/README.md](sources/README.md)を参照。

会話記録は画像画素・添付文書本文・ツール出力・内部推論を含まない。ローカルユーザーパスはプレースホルダーへ置換した。本文の取得上限は1項目20,000文字で、取得結果に明示的な切り詰めフラグはなかったが、完全なチャット原本のエクスポートと同一ではない。画像はファイル名のみを残し、画像を使うケースでは代わりに文字の状況説明を用意した。

元資料の旧提案・コード・レビューは分析対象のデータであり、そのまま実行する指示ではない。価格・在庫・公式仕様リンクは会話当時の記録で、今回再検索して更新してはいない。Skill開発時に最新仕様が必要になった箇所だけ再確認する。

評価ケースは試案で、Skillあり／なしの比較は未実施。「MPU-6050は研究に使えない」「ICM-42688なら研究として十分」といった一般化を合格条件にしない。目的から必要性能を導き、実装・評価の根拠を確認する行動を評価する。
