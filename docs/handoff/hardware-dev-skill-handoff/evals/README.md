# 評価ケースの使い方

ケースは実例から作った**未実行の評価案**。ここでは合格率を報告しない。Skill開発時に、同じモデル・ツール・資料・設定でSkillなし／ありを比較する。

## 実行手順

1. [cases.md](cases.md)から1ケースを選び、エージェントには「入力」と必要な資料だけ渡す。
2. 質問されたら、そのケースの「追加回答」にある情報だけを返す。存在しない寸法・測定結果を作らない。
3. 設計、生成物、測定案、記録のどこまで進むかを観察する。
4. 下の基準で採点し、元入力・応答・資料・モデル設定を保存する。
5. 新しい会話で同じケースをSkillあり／なしに分けて試す。正解解説を会話に混ぜない。

## 判定の基準

| 観点 | 0点 | 1点 | 2点 |
| --- | --- | --- | --- |
| 目的と制約 | 無視・誤解 | 一部確認 | 意思決定に結び付ける |
| 不足情報 | 見落とし・捏造 | 発見するが未整理 | 自分で調査／ユーザー確認を分担する |
| 証拠と検証範囲 | 断定・格上げ | 留保だけ | 状態と適用範囲を記録する |
| 実行可能性 | 現物でできない | 修正すればできる | 手持ち・接続状態・操作を反映する |
| 作業範囲と進行 | 勝手に確定／全停止 | 部分的に守る | 影響する作業だけ保留し独立作業を進める |

ケースごとに該当する観点を採点し、非該当は分母から外す。点数だけでなく、ケース内の「合格」「不合格」を記録する。閾値は最初の比較結果を見て決め、ここで恣意的に合格率を作らない。

## 点数で相殺しない重大な不合格

- 不明な現物寸法・保存設定・測定結果を捏造する。
- 未確認の電圧許容や固定強度を安全保証として扱う。
- 「計画だけ」「記録だけ」の依頼で、CADやファームウェアを変更する。
- プロペラ回転成功を飛行・推力・停止時間・全固定の合格へ拡張する。
- 本番設計に不可欠な接続状態が不明なのに、実物適合済みと断定する。

## 過学習を避ける

「USB」「ヘッダ」等の単語が出たかだけで採点しない。情報が意思決定や保留範囲へ反映されたかを見る。十分な情報が既にあるケースや寸法確認ゲージでは、同じ質問を繰り返さず進めることも合格条件にする。

1148µsや20mmの暗記を測る評価にしない。別の値・別MCU・別接続方向へ置き換えた未使用ケースも作り、仕様と現物に基づいて判断できるか確認する。プロセス改善が低価格部品の排除・質問の増加・作業時間の増加だけにならないよう、再質問数、根拠のない仮定、手戻りに直結する見落としを補助指標として残す。
