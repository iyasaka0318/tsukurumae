# 要件整理

ユーザーの[要件原文](../sources/requirements-user.md)、[会話C084](../sources/conversation.md#c084)、本チャットの実例を整理した。ユーザー要件と、今回の分析から導いた設計候補を分ける。新しいSkillはまだ作成していない。

## 目的と対象

既存のCodex、Claude Code、Cursor等へ読み込ませるSkillとして、ハードウェア開発時の行動方針・思考手順・チェック項目を与える。新しいAIモデルや独自エージェント基盤の開発は目的に含めない。

最大の目的は、**作る前に聞けば防げた手戻りを減らすこと**。ユーザーの質問への回答に加え、最終目的から必要な確認事項を発見し、要求・部品・回路・機械・ソフト・試験をつなげる。

対象はドローン、倒立振子／ロボット、組込み・センサ装置、3Dプリントや電装を伴う小規模試作。最初は本チャットのドローンと倒立ロボットを実例にし、汎用性は段階的に広げる。

## ユーザーが示した開発の順序

| 段階 | 求める振る舞い |
| --- | --- |
| 要求確認 | 目的、用途、成功条件、予算や手持ち品を聞き出す |
| 不足・矛盾の発見 | 明示された条件だけでなく、ユーザーが認識していない論点を見つける |
| 全体計画 | 部品・電源・回路・機構・ソフト・測定系の成立性を合わせる |
| 実装条件の確認 | 現物の端子、接続方向、装着後寸法、固定、アクセスを把握する |
| 設計・実装 | 対象の作業を確定するための条件が揃った範囲から進む |
| 試作と改善 | 結果を記録し、原因を切り分け、影響する箇所を更新する |

これは要件原文の6段階を表にしたもの。各段階の詳細な進行条件は別チャットで検討する。

## 必須としたい能力

### 目的・制約・選定

- 「安い」を「最安なら性能不問」と解釈しない。必要十分な性能と費用の両方を扱う。
- 研究用途では、評価したい現象、測定区間、必要な再現性、交絡要因を把握して選ぶ。
- 部品単価だけでなく数量、送料、付属品、周辺回路、納期まで比較する。
- 手持ち品と購入予定を区別し、調査可能な仕様をユーザーへ丸投げしない。
- 用途変更を検出し、過去の制約を無条件に新プロジェクトへ適用しない。

### 現物・実装・操作

- 型番、派生型、ヘッダの実装有無と方向、接続方式を確認する。
- 基板単体に加え、コネクター装着後、線の曲げ、挿抜、工具、整備の空間を扱う。
- USB・電池交換・ログ回収・調整部へのアクセスを使用手順から導く。
- 固定の対象を明示する。基板・コネクター・ケーブル・試験ボードは別の対象。
- 配線図や手順は、現物で実行できる端子・位置・操作として示す。

### 記録・検証

- 実測、メーカー公称、写真概算、計算、仮定、未決を分け、出典と日付を残す。
- 「CADの簡略ダミーは干渉なし」「実物が組み立つ」「強度を満たす」を区別する。
- 「ビルド成功」「ホストテスト成功」「実機回転」「負荷性能」を区別する。
- 部品交換・接続変更・電源変更時は、依存する寸法・コード・試験を更新する。
- 既存の試験記録を検索し、一致した寸法を保ちながら問題箇所を修正する。

## 質問の設計候補

質問数を増やすこと自体を目的にしない。AIが一次資料で調べる項目と、ユーザーしか分からない現物・運用を分ける。既に回答済みのことを繰り返し聞かない。

最初から長いチェックリストを一括提示せず、次の意思決定に影響する質問を優先する。ユーザーが「俺に聞けば解決することは今聞いて」と求めた場合は、手戻りに直結する現物項目をまとめて確認する。質問と独立した調査・計算は進める。

## 対象外と現時点の境界

この資料作成ではSkill本文、インストール、エージェント設定、ハードウェア設計変更を行わない。新しい機体の製作、独自PCB、独自CAD基盤、完全自動の安全認証、研究の新規性や受賞の保証は要求に含めない。

`i-have-adhd`や`yomiyasu`のような既存Skillは形式の参考。本Skillが特定の人のADHD対応だけに限定されるという要件ではない。説明負担と作業負担を下げる原則を一般化して検討する。
