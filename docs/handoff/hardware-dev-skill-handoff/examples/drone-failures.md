# 失敗・手戻りの分析

元発言と保存済み資料を根拠にした分析。改善候補はまだSkillとして実装していない。失敗だけでなく、うまく切り分けた行動、意図的な探索試験、明示的な用途変更も区別する。

## F01：局所的な価格条件と最終目的

**証拠**：[C008](../sources/conversation.md#c008)、[C014](../sources/conversation.md#c014)、ユーザーの振り返り[C084](../sources/conversation.md#c084)。

ユーザーは「安価でも研究に必要十分」を求めていたと振り返った。ICM-42688への変更を提示し、後にRP2350の制御とTinyML干渉という研究目的を説明した。

**原因の分析**：予算だけを要求と解釈すると、必要な出力周期、通信、割り込み、測定方法との適合を確認できない。元の最安推奨のAI発言はこのチャットにないため、「このAIがMPU-6050を最安だけで確定した」とは断定しない。

**改善候補**：用途・評価指標から必要仕様を導き、性能を満たす最小構成を比較する。IMU交換の理由を型番の格ではなく必要機能で説明する。

**評価**：E02。趣味用へのMPU-6050再採用を失敗にしない対照ケースはE03。

## F02：基板の適合と接続後の適合が別

**証拠**：[C003〜C012](../sources/conversation.md#c003)、[S01](../sources/snapshots/S01-fit-test.md)、[S02](../sources/snapshots/S02-pico-v2.md)。

Pico 2 WHのヘッダは認識済み。基板と穴は合ったが、2.0mmスリットには黒いメスコネクターが入らなかった。3.2mmへ拡幅した試験で挿入はできたが、隙間が緩く左穴がつぶれかけた。最小肉厚0.39mmの部分があった。

**原因の分析**：金属ピン、ヘッダ樹脂、メスハウジング、取付ボスを同時に扱う必要がある。単なる開口拡幅では保持・支持が悪化する。2.0mmゲージは未適合を調べる試験として生成されているので、探索試験の不合格を全て予防可能な失敗には数えない。

**改善候補**：本番CADの確定前には装着状態を確認する。代表品寸法は現物同一型番の確定値にしない。既に合った穴位置を保ち、スリットと支持を個別に試験する。

**評価**：E01、E04、E12。

## F03：上向きヘッダ・作業空間を簡略CADから落とした

**証拠**：[C057](../sources/conversation.md#c057)、[C065〜C070](../sources/conversation.md#c065)、[S03](../sources/snapshots/S03-wiring-plan.md)、[S09](../sources/snapshots/S09-drone-v1.md)。

初版CAD生成後、GY-521とMINI360は部品側へヘッダが出ていると判明。AIも未反映を認めた。MINI360は接続後20mmで、初版の絶縁込み6mmの簡略予約では不足した。

**原因の分析**：型番や基板外形から接続後状態を仮定した。コネクター・曲げ・抜き差し・電圧調整の空間を別に扱わなかった。

**改善候補**：写真は方向と出口、ユーザー実測は高さ、メーカー図面は公称形状に使う。「20mm」へ曲げと作業空間を追加する。ユーザーの「計画だけ」に従い、CADは更新しない。

**評価**：E05、E13。

## F04：費用・入手性の条件が後から具体化

**証拠**：[C017〜C021](../sources/conversation.md#c017)、[C029〜C040](../sources/conversation.md#c029)。

メーカー資料の充実した高価格候補から、ユーザーが繰り返し安さと国内入手性を要求。最終的にモーター2個約3,000円を目標とし、FIT0450／マルツへ選定が進んだ。

**原因の分析**：必要性能を超える小型金属ギヤ品に寄せたこと、数量・送料・地域・納期を含む制約の確認が遅れたこと。予算自体が会話で具体化した部分もあり、全検索を無駄と扱わない。

**改善候補**：数量と送料込みの比較を用意する。公式データの同型番という条件を守り、無名品へ単純に置き換えない。安いモーターの重量・信号電圧・必要周辺回路も比較する。

**評価**：E06。

## F05：推奨値・写真診断・実測合格の混同

**証拠**：[C006](../sources/conversation.md#c006)、[C056](../sources/conversation.md#c056)、[S01](../sources/snapshots/S01-fit-test.md)。

最初の回答でモーター穴2.2mmを採用値のように列挙したが、実際に一致した試験穴は2.4mm。後の記録で2.2mmは未検証の本番推奨と区別した。下面の隙間は初期回答でZオフセットが主因と断定したが、その後は推定として記録した。

**原因の分析**：実物で確認した値と設計候補、観察と原因診断を同じ確度で提示した。2.0mmと2.1mmの穴は高さや用途も異なる。

**改善候補**：値に用途・材料・試験形状・出典・確認状態を付ける。写真だけで原因を確定しない。プリセットに未測定の校正値を入れない。

**評価**：E07、E08。

## F06：説明は正しくても操作の負担が大きい

**証拠**：[C010](../sources/conversation.md#c010)、[C055](../sources/conversation.md#c055)、[C073〜C074](../sources/conversation.md#c073)。

「ボスを上向き」「ブリムなし」だけでは操作箇所や向きが分からない。外付け抵抗の二股と開始スイッチの表現も、手持ちジャンパで何をするか分からなかった。

**原因の分析**：技術用語や電気的な意味と、ユーザーが現物で実行する操作の間が埋まっていない。

**改善候補**：設定ファイルや3MFで再現可能にする。ただしプロセスJSONとモデルの向き・倍率は別。開始線は「未接続→GNDへ挿したまま→離す」で示す。外付け部品を減らすなら対象MCUの起動状態を検証し、理由を明記する。

**評価**：E08、E09。RP2040内蔵プルダウンの単体試験実績をRP2350へ転用しない。

## F07：ホストテスト合格でも、実機を始動できる指令ではなかった

**証拠**：[C072〜C079](../sources/conversation.md#c072)、[S08](../sources/snapshots/S08-motor-test.md)。

停止1000µs・上限1100µsのファームウェアはビルドと開始停止テストに通ったが回らなかった。BLHeli_S公式の標準最小スロットル1148µsと照合後、1200µs版で回った。

**原因の分析**：状態遷移・上限を守るテストはあっても、上限が対象ESCの始動範囲へ届くかを点検していなかった。接続操作の誤解は先に確認したが、それだけを原因と決めず生成物側も調べる必要があった。

**改善候補**：単位、周期、停止点、最低始動値、最大値、プロトコル、個体設定を仕様から導く。実機失敗時は操作・配線・電源・指令の仮説を切り分ける。安全制限を外した全開試験へ進まない。

**評価**：E10。実物の保存設定や正確な最小始動パルスは未読なので、1148µsを個体の実測値にはしない。

## F08：測定可能な端子と測定の限界

**証拠**：[C076〜C078](../sources/conversation.md#c076)。

測定の黒プローブへ物理38番を指定したが、そこは給電配線で使用中だった。ユーザーが指摘し、空いている物理3番のGNDを使った。測定は3.27V／0.14V。

**原因の分析**：論理的に正しい測定点でも、実際にアクセスできるとは限らない。

**改善候補**：同じ配線状態で使える測定点・基準点を示す。給電GNDを抜かせない。DC平均0.14VからPWM周期やパルス幅を保証しない点は、この会話では適切に留保していた。

**評価**：E11。

## F09：改善結果がファイルへ残らない

**証拠**：[C011〜C012](../sources/conversation.md#c011)、[C056](../sources/conversation.md#c056)、[S01](../sources/snapshots/S01-fit-test.md)。

最初の印刷結果は記録済みだったが、3.2mmスリットの緩さと左穴の変形は、後からユーザーが過去記録を探すよう依頼した時にファイルへ追記した。

**原因の分析**：会話で受け取った結果と、次回の設計が参照する記録が同期していなかった。

**改善候補**：試験版、条件、報告、未測定、採否を受領時に更新する。「緩い」の対象を確認したことは良い行動で、その解消結果も一緒に残す。

**評価**：E04、E07。

## F10：確認した動作から、未確認の性能へ広げる危険

**証拠**：[C079〜C083](../sources/conversation.md#c079)、[S08](../sources/snapshots/S08-motor-test.md)。

回転成功後の短い「おｋ」と、プロペラ回転成功が得られた。モーターをテスト板にねじ固定したことは分かるが、ボード自体の台固定方法への質問には回答がない。

**原因の分析**：回転・停止指令・実停止時間・荷重・固定・飛行は別の確認である。短い承認から、全停止経路や安全性をまとめて検証済みとするのは証拠を越える。

**改善候補**：成功はそのまま記録し、試験した範囲だけを合格扱いする。固定の対象を明示し、プロペラ付き試験と飛行・耐久試験を分ける。

**評価**：E14、E15。
