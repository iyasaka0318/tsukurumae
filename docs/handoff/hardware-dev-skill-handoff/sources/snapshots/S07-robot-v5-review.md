## 結論

モーター電源スイッチを左右mini360の入力側へ置き、固定5V・Pico・IMU・エンコーダの給電を残す構成は、試行中のUSB常時接続を外す目的に整合する。USB挿抜予約とB電池台の位置を維持する扱いも整合している。

基本部品3,530円＋回生評価850円＋追加コンデンサ100円＝4,480円の内訳、本体と車輪を分けた質量・重心の計算、ローカルリンクを確認した。配置JSONにある平面予約とUSB挿抜予約の非重複も一致する。注文状況はv5に記載された情報として扱い、注文履歴を独立に確認したものではない。

## 実装前に明記する点

### 1. 停止時にログを凍結する

給電継続とログの保持は別の条件。詳細タイミングは直前約2.048秒のリングなので、停止後も1kHzで同じリングへ記録を続けると、USBを挿す前に停止直前の記録が上書きされる。通常終了・STOP・傾角停止・VM低下等の各停止経路で、実験ログの書込みを止める仕様を追加する。

停止を検出したCore0はINをLL固定し、停止時刻・最初の停止理由・最後の有効レコード番号を保存して、物理ログ・タイミングリング・試行集計を凍結する。その後のVM低下等で最初の理由を上書きせず、必要な後続情報は別の小さい状態欄へ記録する。新試行の明示開始までログを再初期化しない。watchdog再起動からの回収状態も同じ凍結状態とする。

停止後はCore0で回収・電池監視を続ける。通常試行中の「制御完了でのみwatchdog更新」を停止後にどう切り替えるかも明記し、回収中の無意味な4msリセットループを防ぐ。Core1からwatchdogを更新して制御停止を隠す方式にはしない。停止から5秒以上待ってUSBを接続し、末尾番号・停止理由・停止直前の内容が変わらず回収できることを追加確認する。

### 2. 外部測定線の外力は残る

試行中のUSBケーブルはなくなるが、DRDY→GPIOの全応答計測を外部ロジックアナライザで行う試行には、DRDY・GPIO・GNDの測定線が接続される。「ケーブルの外力が交絡要因から外れる」はUSBケーブルに限定する。

測定ヘッダー近くにフレーム固定点を設け、同じ線材・束ね方・余長・外部支持点を比較条件間で固定する。±8°の傾きと予定移動範囲で張らず、車輪・床へ接触しないことを確認する。外部測定あり／なしの試行を識別する。USB用C1の再採用を意味せず、測定ヘッダーの位置から別に決める。

### 3. 全OFF時の残留電圧を確認する

MASTER_SWを全負荷の上流へ置くことで、制御系だけをスイッチで切る誤操作は避けられる。しかし、VMには左右470µFがあり、車輪の回転中は回生もあるため、全OFF操作で全ノードが同時に0Vになるとは言えない。v5の「無給電PicoへVM監視電圧がかかる状態が配線上起こらない」は、定常的なスイッチ状態についての説明へ限定する。

全OFFの運用はモーター電源OFF・車輪停止・VM残留の確認を先に行い、ログ保存後にUSB／XT30／MASTER_SWで制御系を切る順に整理する。固定5V・Pico 3.3V・左右VMの立上り／立下りと監視線への電圧を実測し、監視入力の給電条件を満たすことを確認する。放電待ち時間や追加放電抵抗の要否はこの測定後に決め、今の段階で部品追加を必須とはしない。
