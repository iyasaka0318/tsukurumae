# ハードウェア開発支援Skill 要件整理

## 1. このSkillで実現したいこと

Codex、Claude Code、Cursor等の既存AIエージェントに読み込ませて使用する、ハードウェア開発支援用のSkillを作りたい。

新しいAIモデルや独自のAIエージェント基盤を一から開発したいわけではない。

`i-have-adhd` や `yomiyasu` のように、既存AIに一定の行動方針・思考手順・チェック項目を与えることで、ハードウェア開発時のAIの振る舞いを改善する「便利ツール」の一つとして作りたい。

対象は特定のドローンだけではなく、将来的には、

- ドローン
- 倒立振子
- ロボット
- 組込みシステム
- センサを使う装置
- 3Dプリントを伴う試作
- 電装を含む個人開発
- その他の小規模なハードウェア開発

などにもある程度汎用的に使えるものを目指したい。

ただし、最初から完全な汎用品を作る必要はない。まず自分自身のドローン開発や倒立振子開発などを実例として使いながら改善していけばよい。

# 2. このSkillを作りたい理由

現在のAIは、ユーザーが「これを作りたい」と伝えると、かなり早い段階で具体的な部品選定、CAD設計、コード生成などへ進んでしまうことがある。

しかしハードウェア開発では、ユーザー自身が「何を決めなければならないか」を認識していないことが多い。

その状態でAIがユーザーから明示的に与えられた情報だけを使って先へ進むと、後から重要な条件が判明し、大量の手戻りが発生する。

今回のドローン開発でも実際にその問題が発生した。

たとえばIMUについて、当初「安い方がいい」という条件からMPU-6050が候補になった。

しかし本来の要求は、

「価格を抑えたいが、研究用途として必要十分な性能は確保したい」

であり、

「最安であれば性能は問わない」

ではなかった。

研究内容や評価目的まで考えると、後からICM-42688系の方が適切だという判断になった。

つまり、ユーザーが与えた局所的な条件だけに反応して部品を決めるのではなく、

「この部品は最終目的に対して本当に十分か」

まで確認してから決定する必要がある。

同じ問題はCAD設計でも発生した。

使用する部品の商品名や型番はAIに伝えていたが、

- Pico 2なのかPico 2 WHなのか
- ピンヘッダーが付いているのか
- ピンヘッダーをどちら向きに使用するのか
- ジャンパ線を使用するのか
- 直接はんだ付けするのか
- IMU側にピンヘッダーを付けるのか
- USB端子に完成後もアクセスする必要があるのか
- バッテリーケーブルやコネクタがどの方向から出るのか
- ケーブルを挿した状態で必要な高さはいくらか
- 部品の固定方法は何か

などを十分確認しないままCAD設計が進んだ。

その結果、

「ピンヘッダーがあるのでこの向きでは使えない」

「ジャンパ線を挿したら高さが足りない」

「ケーブルがこちら側から出るので設計変更が必要」

などの問題が後から発生し、何度もモデル修正が必要になった。

このような、

**作る前に聞けば防げた手戻り**

を減らすことが、このSkillの最大の目的である。

# 3. 基本思想

AIは、ハードウェア開発時に単なる「質問への回答者」として振る舞うのではなく、

1. 要求を聞き出す
2. 不足・矛盾・未決定事項を発見する
3. システム全体として成立する計画を作る
4. 具体設計に必要な実装条件を確認する
5. 条件が揃ってから設計・実装へ進む
6. 試作結果を受け取って改善ループを回す

という順序で動いてほしい。

重要なのは、

**ユーザーが質問した項目だけを見るのではなく、最終目的から逆算して「まだ何を確認する必要があるか」をAI側から考えること。**

ユーザーが知っていることを答えさせるだけでは不十分。

ユーザー自身が存在を認識していない論点、つまり「何を質問すべきかすら分かっていない項目」をAI側から発見してほしい。
